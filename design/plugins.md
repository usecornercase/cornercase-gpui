# Plugins

Code: `src/panels/plugins.rs`, `src/panels/plugins/`

- **Like the TUI's Settings › Plugins, with no catalogue**: what is installed or linked, whether it is on, what it asks for and runs, its actions and its log; turning each on and off, linking a folder, installing, updating and removing. Finding plugins is the website's job.
- **The list is read again each time the sheet opens**: `plugin list --json` reads the plugins from the files, `plugin actions --json` asks the server for their actions and `plugin status --json` (#469 upstream) for what each service is doing. Without a server, or with an older one, there are no actions and no service states, and the list stays. `list` stays the source of the cards rather than `status`, which carries the same plugins, because it works with no server.
- **A plugin's source is kept as JSON** (`{"kind":"link","path"}` or `{"kind":"git","repo","url","ref","subdir","commit","path"}`), so a kind added later still reads; an unknown kind is shown by name.
- **Turning one on is the explicit step**, so it asks first and says plainly what that means: it runs as you, what it asks for is shown, not enforced, and what it runs. Turning off asks nothing. Plugins start off.
- **Removing an installed plugin deletes its copy; unlinking a linked one only forgets it**: both ask, with the difference spelled out, and settings and data stay.
- **The confirmation is this sheet's own small dialog** (`plugins/ask.rs`), since `dialogs::confirm` runs a command and these steps run a closure that marks the plugin busy and reloads. It can carry a scrolled block of monospaced lines, for a preview, drawn as the log is.
- **Linking on another machine asks for the folder's path** (`dialogs::ask_path`): the folder picker shows this Mac's disk (`design/remote.md`).
- **Install and update are previewed and confirmed in the window** (#468 upstream; `plugins/fetch.rs`, `plugins/install.rs`): `plugin install SOURCE --preview --json` fetches and prints what installing runs, installing nothing; the dialog shows its `lines` as cornercase writes them (the same preview the terminal prints, with hidden characters already escaped), so the app never words its own version of what a plugin runs. Yes runs `plugin install SOURCE --commit SHA --yes` with the commit the preview printed: cornercase refuses when the source gives another commit by then, so what installs is what was read. `--yes` is still needed beside `--commit`, since there is no terminal to ask in (cornercase 0.12.225). Nothing needs a terminal tab any more, so the old tab and its shell quoting are gone.
- **The toast after installing or updating is the app's own** (`installed Notch 0.1.1, turned off`), from the preview: without `--preview` the command prints `fetching…`, the whole preview and then the outcome on stdout, with no `--json`, and its first line is the fetch.
- **Updating previews every plugin first**: `plugin update ID --preview --json` takes one ID (`--json` and `--commit` require it), so Update all previews each installed plugin, all at once, and asks once with every changed plugin's preview under a `name: old → new` line; one up to date prints only `id`, `commit` and `up_to_date`, and is told in a toast. A failed preview (a linked plugin, no network) is its own toast and does not hold the others. On yes the updates run one after another, each `plugin update ID --commit SHA --yes`, since each rewrites `plugins.json`. The single Update… takes the same path with one ID.
- **The preview's shape** was read on cornercase 0.12.225 with `plugin install jacogaz/cornercase-notch --preview --json` (October 2026; `tests/fixtures/plugins/install-preview.json`). The update and status fixtures follow `Details`, `UpdatePreview` and `PluginsInfo` in cornercase's sources, since getting real ones means installing or turning on a plugin on this machine.
- **Service states come from `plugin status --json`**: a card of a plugin that is on and has services shows a chip per service, `running, pid N` in green, `stopped, restarting in N s` in red, `starting` (or a state added later, by name) in amber. Without a server the card says that the state needs it. `problem` (`plugins.json` cannot be read) is shown above the list.
- **Actions run on what the window shows**: a `button` action takes no target; otherwise the most precise of its contexts the window shows (pane, tab, workspace, project), and none when it shows none. `plugin run` gets the revision the actions were listed at and refuses a stale one.
- **A failed action exits with 1 but still prints its outcome**, which the toast reads; an error before it ran (a stale revision, no server) prints nothing, and the error is shown instead.
- **Popup actions run from the sheet too** (#456 upstream): running one closes the sheet so the popup shows over the terminal (`design/terminal.md`), and the button stays busy until it closes, since `plugin run` answers only then. cornercase opens a popup only while its own window is attached (`no window is attached` otherwise, shown as the toast) and sizes it from that window, not from this one's view; neither can be changed from here.
- **What runs is a job in the store** (`plugin:` keys, `design/connection.md`): the card's on/off chip turns into a spinner, and an action, Update, Install, Link folder and Update all become busy buttons that say what they do (`Fetching…`, `Installing…`, `Checking…`, `Linking…`); the status bar names it, so a popup action that closed the sheet still shows. Checking for updates has its own key: it shared the plugin's, so Update read `Checking…` while the plugin turned on or off.
- **The log shows the last 60 lines** (`plugin logs ID -n 60`) and is read again with the list.
- **On another machine the sheet only reads and runs**: cornercase's `plugin` commands that install, update, remove, link, turn on or off, list or show logs act on the files of the machine they run on and refuse `--remote`; only `plugin status`, `actions` and `run` ask the server. So there the list comes from `plugin status --json` (it carries every plugin's fields), the switches and the install, update, remove and log buttons are gone, and a note says to run `cornercase plugin …` on that machine. Noted for upstream.
