# Files panel

Code: `panels/files.rs`, `panels/files/` (`source.rs` picks the disk or the command line, `served.rs` reads `cornercase files`, `finder.rs` the ⇧⌘P finder, `peek.rs` and `peek/` the card of a path under the pointer)

The workspace's files: a tree, a viewer and a search. It follows the TUI's panel (cornercase's `design/files-panel.md`).

## Reading the disk

- **The panel reads the disk itself**, the one exception to going through the command line (#345 upstream, `design/upstream-gaps.md`): a file viewer through `cornercase` would copy every file through a process.
- **On another machine** (`design/remote.md`) the panel asks cornercase there, through `cornercase files` (#477 upstream): this Mac's disk at the same path would show other files, or none. See "Through the command line" below.
- **Nothing blocks the window**: listings, reads, highlighting and searches run off the main thread, and each answer is dropped when what it answers is no longer shown (another workspace, another file, a newer query).
- **Polling, not watching**: while the panel shows, the open file's size and modification time are checked every second (`CHECK_EVERY`) and the open folders are listed again every second check (`LIST_EVERY`), so what an agent writes appears. A closed panel polls nothing.

## Per workspace

- The panel follows the shown workspace and keeps, per workspace and in memory, the open folders, the open file (marked in the tree once closed) and the query. Coming back to a workspace brings its query back; a workspace whose folder changed starts afresh.
- A folder that went away closes; a root that cannot be listed shows why.
- Closing the viewer scrolls the tree to the file's row.

## The tree (`tree.rs`)

- **Each open folder is listed on its own, one level deep**, then flattened into rows. A huge folder (a home folder opened as a project) costs nothing until it is opened. At most `MAX_ENTRIES` per folder; the panel says when some were left out.
- The `ignore` rules apply (`.gitignore`, `.ignore`, the global and `.git/info/exclude` ones, also from parent folders, without needing a git repository). `.git` is never listed; hidden files are, and the eye in the tree's header hides them.
- **A row is clickable across the panel's whole width**, as in Finder and editors (asked for on 2026-10-30): gpui 0.2.2 lays a `uniform_list` item out at its content's width unless it is `w_full`, so the hover and the click stopped at the name. Search results take the whole width too.
- **The look** (asked for on 2026-10-30, the old `▸ ▪ •` glyphs read as noise): Lucide chevrons, then the icon of the file's type (`ui::file_icons`, `design/widgets.md`), the same as the TUI's; a level indents 18 px, which puts a folder's children's icons under its name. The search results and the viewer's title show the same icons. The selected row (the open file, or the menu's) is lit as rows are elsewhere (`design/widgets.md`) and does not hover.
- **The header names the root folder**, its full path in a tooltip: a long path cut off at the panel's edge said less than the name. It holds the tree's own controls as icon buttons with tooltips: hidden files (an eye, crossed out while they are hidden; a tint would have lit it all the time, since they show by default) and collapse all. They left the search bar, whose results they do not touch.
- A link to a folder opens like a folder. A folder that is gone fails as `read_dir` would rather than listing nothing.
- Opening a file from a search opens every folder above it (`reveal`), so it shows in the tree.

## The viewer (`disk.rs`, `highlight.rs`)

- **Only regular files are read**: a link to `/dev/zero` or a FIFO would never end.
- The first 16 bytes say whether a file is an image (PNG, JPEG, GIF, WebP, BMP, TIFF; SVG by extension), which may be up to 32 MB; text stops at 8 MB. The read stops one byte past the cap, so a file that grew since the size check cannot get past it.
- A NUL in the first 8,000 bytes makes a file binary. Invalid UTF-8 is replaced, not refused. Tabs are drawn as four spaces, `\r` is dropped and a final newline ends the last line rather than starting an empty one.
- **Colours never flash**: the first read shows plain text at once and the colours after; a re-read after a change answers only once coloured.
- A selected line past the end (the file shrank) selects nothing.
- **A long line ends in "…" at the panel's edge**, as long names do (`design/widgets.md`): the viewer does not scroll sideways. Each line spans the panel, so the selected line's tint does too. The title gives the file's name at most 60 % of its row and the folder the rest, both cut the same way, as Changes shows its open file. Checked live on 2026-10-31. Their boxes, the tree header's and `ellipsis` are flex containers, or the names were left 0 px wide and the title showed only the icon (`design/widgets.md`, fixed the same day).
- **Highlighting uses syntect's default grammars**, with scopes mapped to a few kinds drawn in the palette's colours as the TUI does: keyword magenta, function blue, type cyan, string green, number and constant yellow, property and tag red, comment grey in italics. The grammar is found by file name (`Makefile`), then extension, then first line (a shebang); extensions the default set lacks borrow a close relative (TypeScript as JavaScript, TOML as INI, Swift and Kotlin as Java, Vue and Svelte as HTML). Lines are parsed in order so the state carries across them (block comments, strings); a grammar that fails leaves the rest plain.
- Sources over 1 MB stay plain: syntect's pure-Rust regexes are slow on big files.
- A text search's query stays lit in the opened file.

## The search (`search.rs`)

- **One index of paths, reused**: a single `ignore` walk (hidden files included, ignored ones and `.git` not), at most 200,000 paths, reused by new queries for 10 seconds (`INDEX_FRESH`). A walk cut short, by a newer query or by the finder closing, gives no index: until 2026-10-31 its partial list was kept and reused, so for 10 s a fast typist's later queries missed files.
- **File names**: nucleo's matcher with fzf's scoring and smart case; on a tie a file whose own name matches the whole query, then the shorter file name, then the shorter path, so the file a query names comes first. At most 200 results. The first tie-break came with the finder (2026-10-31), as fzf's `pathname` tiebreak: nucleo scores a match in a folder's name as one in the file's, so “finder” listed `finder/view.rs` and `finder/tests.rs` before `finder.rs`, the shorter names winning the tie. cornercase's own ranking (the TUI, and `files search --names` on another machine) has only the other two, so there such ties still go to the shorter name until it adopts this.
- **Text**: ripgrep's searcher, the query a literal with smart case, binary files skipped, on up to 8 threads. At most 1,000 matches: each match takes a slot before it is kept, so the threads together never keep more than the cap. A long line is cut to 400 characters, starting 40 before its first match.
- Enter opens the first result; pressed before the answer came, it opens it when it does.

## Going to a file (`finder.rs`, ⇧⌘P)

- **A quick open over the window, as VS Code's Go to File** (asked for on 2026-10-31): a field, and the files ranked as you type by the panel's own name search (above: nucleo, fzf's scoring, at most 200), each with its type's icon, the matched letters lit and its folder dimmed beside the name, drawn by the panel's own result row. ↑ ↓ (and Page Up, Page Down) choose; ↩ or a click opens the file in the panel's viewer, revealed in its tree (`reveal`: the folders above it open), and docks the panel. A sheet over the window closes too, or it would hide the file. The keys go back to the terminal as the dialog closes, since the viewer only reads.
- **"The selected project" is the shown workspace's folder**: the project's checkout, or the worktree when a worktree's workspace is shown. It is the folder the panel shows and opens the file in. Rejected: every workspace of the project (each file once per worktree, and the panel shows one at a time) and the project's main folder while a worktree is shown (another branch's files, opened in a panel that shows this one). The footer names the place (`project › workspace`), and the finder follows the shown workspace while it is open.
- **The panel's index, not a second one**: opening starts the walk (`search::index`) unless the panel walked that folder less than 10 s ago, so it is often done by the second letter; letters typed meanwhile wait for it rather than each starting a walk, and the walk is handed to the panel (`keep_index`), whose next search reuses it. The opening keeps its index until it closes: a file written while it is open shows on the next opening. On another machine there is no index here: each query is `files search --names` through the panel's `Source`, as its own search. A newer query drops the older answer, and ↩ before the answer opens the first file when it comes, as the panel's Enter.
- **A dialog** (`Store::show_dialog`), not a sheet or a panel of its own: the host already gives it the veil, the rise, a click outside that closes it and the rule of one dialog at a time. It is centred like every dialog, at a height fixed by the window's (`frame_for`), so the field never moves as results come and go; a list that grew and shrank in a centred card would. `Root` builds the Files panel to hand it over (`Root::panel`), so the panel and its index exist even if it was never opened. ⇧⌘P closes it again, as a sheet's key closes the sheet; the other ⌘ shortcuts are ignored under it, as under any dialog.
- **Escape clears the query, then closes**, as the Search sheet and every search field here (`clears_on_escape`, `design/terminal.md`). Rejected: closing at once with a query typed, as VS Code does, which would make this the one search field that behaves otherwise.
- **Each opening starts empty**, as the Search sheet; an empty query shows a hint, not recently opened files, since the panel keeps only the last file of each workspace.
- **The panel's own query is kept**: the viewer's back button then says "‹ Results", since closing it shows them, and "‹ Files" otherwise.
- **Checked live** on 2026-10-31 with cornercase 0.12.230, in a throwaway project holding a copy of `src` and `design`: ⇧⌘P over the terminal and over a sheet (which closed), the ranking as you type and its tie-break, ↑ ↓, ↩, ↩ typed right after the query, a click, no match, Escape clearing then closing, ⇧⌘P closing it, the file opened in the viewer and revealed in the tree, long names cut. Through `--remote` (a local sshd and an isolated server): the server's `files search --names` answers, and a file opened through `files read`.

## Peeking at a path (`peek.rs`, `peek/`)

- **Resting the pointer on a path a pane printed shows the file in a card** (asked for on 2026-10-31: the TUI opens a path in this panel on a click, and a window can show far more kinds of file than a terminal). How the path is found, underlined and clicked is in `design/terminal.md`; the card belongs here because it reads the disk as this panel does, and on another machine through the same `Source`.
- **It waits 350 ms** (`PEEK_AFTER`), so moving across text does not flash cards, **and closes 280 ms after the pointer has left both the path and the card** (`GRACE`), so the pointer can cross into it to scroll, pause a video or press its buttons. Typing, the wheel and a click close it at once. Another path of the same file and lines moves the card without reading it again.
- **Beside the path when 420 px fit on its right, else below, or above when there is more room there** (`place.rs`). Found live: a card below the first of a column of paths (`ls`, `git status`) covered the next ones, and the pointer moving down onto it kept it open; beside, the column stays free. At most 660 px wide, as tall as the room allows.
- **Opaque** (`raised` behind the header, `pane` behind the body): the glass of floating cards let the terminal's text show through and the code was hard to read (found live).
- **What it shows**, by kind:
  - **Text**: read as the viewer reads it (8 MB at most), coloured by the same highlighter in the background, scrolled to three lines above the path's first line, with its lines lit. The header gives the lines, the count and the language. A click on a line opens the panel at that line.
  - **Pictures**: the viewer's formats, the card sized from the picture's header (the `image` crate reads only the header), so it fits without bands. A GIF moves: gpui animates an `img` only when it has an id, which the viewer's picture lacked too and now has.
  - **Videos** (`mp4`, `m4v`, `mov`, `3gp`): AVFoundation's `AVPlayer` with an `AVPlayerItemVideoOutput` asked for `420f` (full-range bi-planar YUV) and Metal-compatible buffers, drawn by gpui's `surface` element. gpui's Metal renderer asserts that exact format, so a frame in any other is dropped rather than drawn. It plays without sound and loops; a click pauses it, the speaker turns the sound on. While it plays the card asks for every display frame and copies a new buffer when there is one; only the card redraws, not the terminal. A file AVFoundation cannot open (WebM, MKV) falls back to Quick Look's thumbnail.
  - **Sounds**: the same player without the video output, which never starts on its own (a card that appears under a resting pointer must not make noise): a play button, the progress and the time.
  - **Anything else** (PDF, Office and iWork documents, fonts, 3D models, a binary or a file over 8 MB): `qlmanage -t -s 900` into a temporary folder, its PNG read and the folder removed, killed after 8 s. Without a thumbnail the card says there is no preview.
- **On Linux** (decided 2026-11-04): there is no Quick Look and no AVFoundation, so `peek/player.rs` is replaced by `peek/no_player.rs` (it opens nothing) and anything else goes to the freedesktop thumbnailers (`peek/thumbnailers.rs`), which file managers already use: the file's type from shared-mime-info's `mime/globs2` of every XDG data folder, ranked together as GLib's xdgmime merges them, a tie going to the folder that comes first (`$XDG_DATA_HOME`); until 2026-11-04 the first folder with any match decided, so a user's `*.gz` hid the system's `*.tar.gz` (by name, the longest glob of the highest weight, case-insensitive unless marked `cs`, each matched as `fnmatch` does, with `*`, `?` and bracket expressions such as `*.anim[1-9j]` and `*.so.[0-9]*`, as the spec asks; until 2026-11-04 only literal names and `*` before a suffix matched), then the first `thumbnailers/*.thumbnailer` entry, in those folders and in name order, that lists the type and whose `TryExec` (else its command) runs, its `Exec` split into words as the desktop entry spec quotes them (double quotes with `\` before `"`, `` ` ``, `$` and `\`; single quotes and a `\` outside quotes as GLib's `g_shell_parse_argv`, which GNOME's thumbnailer code uses, so `--size="%s"` is one word) and filled in word by word (`%i` the path, `%u` its URI, `%o` the PNG, `%s` 900), the paths as they are on disk, so a path with spaces or bytes that are not UTF-8 stays one argument and no shell reads it. It runs under the same 8 s limit as `qlmanage`. **Its temporary folder is private** (`desktop::Scratch`, shared with Quick Look): Linux's `/tmp` is shared by every user, unlike macOS's per-user temporary folder, so the folder is made with mode 0700 and must not exist yet (a name someone else took is skipped for the next), and it is removed when the thumbnail is read or anything fails. Before 2026-11-04 it was `create_dir_all` on a predictable name, which accepted a folder another user had made (with a link inside, the thumbnailer wrote through it), and an `Exec` the app could not fill left it behind. So a PDF shows with Evince's or Papers' thumbnailer, a video with `ffmpegthumbnailer`'s, a font with GNOME's, a document with LibreOffice's, when installed. A video or a sound says plainly that it plays only on macOS, in the header (beside its thumbnail when there is one) or as the card's note, which points at the header's default-app button. Without a thumbnailer the note says that none on this computer reads the type; one that ran and failed is named with how (its exit status, the 8 s limit, no picture written), since "none reads it" would be false and give no reason (before 2026-11-04 both said the same). A video or a sound keeps its own note either way: there the thumbnail is only extra. The picture is read up to 32 MB, the viewer's limit for an image, and refused past it, so a thumbnailer that writes a huge file cannot fill the memory; `qlmanage`'s picture is read the same way.
  - Checked live on 2026-11-04 (the same container, two thumbnailers written for the check in `~/.local/share/thumbnailers`): `clip.anim5` took `video/x-anim` from `*.anim[1-9j]` and showed the picture its thumbnailer drew; a PDF whose thumbnailer exits with 3 said "sh ended with exit status: 3." (its `TryExec` names it); a binary file with no type still said that none reads it.
  - Checked live on 2026-11-04 in the same container, with `ffmpegthumbnailer` 2.2.3 installed: resting on `clip.mp4` showed its thumbnail (with the film strip `-f` asks for) and "Plays only on macOS" in the header, whose default-app button ran `xdg-open /tmp/demo/clip.mp4`; `tone.wav` showed the note "Plays only on macOS"; a binary file "No thumbnailer on this computer reads this kind of file". Not checked: a PDF, a font or a document (no such thumbnailer installed), and a thumbnailer that hangs.
  - Rejected: sniffing the type with `file --mime-type` or `xdg-mime` (a process per peek, and libmagic's names differ from the ones thumbnailers list, such as `font/sfnt` for `font/ttf`); a video player of our own (GStreamer or ffmpeg bindings, a large dependency for a hover card); running thumbnailers in `bwrap` as GNOME does (not on every machine; the user installed them to make pictures of their own files).
- **On Windows** (decided 2026-11-04): no Quick Look, no AVFoundation and no freedesktop thumbnailers, so `peek/no_player.rs` stands in for the player, as on Linux, and anything else asks the shell for the picture File Explorer shows (`peek/shell.rs`): `SHCreateItemFromParsingName` then `IShellItemImageFactory::GetImage` at 900 px with `SIIGBF_RESIZETOFIT | SIIGBF_THUMBNAILONLY`, so the thumbnail handlers Windows and the user's apps installed answer (PDFs, videos through Media Foundation, Office files, fonts) and a type without one gives no picture rather than its icon, which says nothing about the file. Each peek runs it on a thread of its own, which sets up COM apartment-threaded and takes it down when the shell answers, under the 8 s limit of the other helpers: a handler that hangs leaves the card saying Windows made no thumbnail within 8 s, its thread finishing on its own (a thread cannot be killed; the handlers run in a surrogate process when Windows isolates them). The `HBITMAP` is read with `GetDIBits` as 32-bit top-down BGRA and turned into a PNG for gpui: an alpha that is zero everywhere is a thumbnail without one (opaque), any other is premultiplied, as GDI's are, and is taken out. A video or a sound keeps "Plays only on macOS", in the header beside its thumbnail or as the note; any other type without a thumbnail says "Windows has no preview for this kind of file", and one the shell could not find or read says why. Rejected: `IThumbnailCache` (more calls for the same picture), `SIIGBF_ICONONLY` as a fallback (an icon is not a preview), WIC to encode the PNG (the `image` crate already does it here). The paths reach it as Windows writes them: a link's `path` is the canonical one cornercase gives, and one that reaches the network is no link there (its `design/windows/network-paths.md`), so a peek never opens a share. Checked only by cross-compiling and unit tests on macOS (the pixel conversion, the PNG, the deadline); no thumbnail has been asked of a real Windows yet.
- **The header** opens the file in this panel (at its lines) and, on this machine, in its default app (`desktop::open`, a job that toasts its failure).
- **The same card shows a web page** under the pointer (`peek/web.rs`), with the Browser panel's picture of it; why and how are in `design/terminal.md`. One card for both keeps one look, one delay and one way to close.
- **Rejected**: a native `AVPlayerLayer` view over the window (gpui draws into one Metal layer; a native view sits above every gpui overlay, toast and menu included, and has to be moved by hand); decoding with `ffmpeg` (not on every Mac); `qlmanage -p` (its own window, outside this one); `QLThumbnailGenerator` through its block API (more unsafe code for the same picture); the `objc` crate, whose macros trip `unexpected_cfgs` in this crate, for `objc2`, which also checks every message's argument and return types in debug builds.
- **Pitfall**: `core-video`'s `CVPixelBuffer::get_io_surface` takes ownership of a reference it does not own and over-releases it; a prototype crashed on it, so it is not used.
- **On another machine** the card reads text and pictures through `files read` (an absolute path is passed as it is, see below); videos, sounds and documents say that only text and pictures are shown from there, since the player and Quick Look need the file on this Mac. Not checked live through `--remote`.

## Paths on Windows and across machines

- **The panel follows its root's rules** (`Place::style`, from the form of the workspace's folder, `design/remote.md`): the disk's on this machine, the server's through `cornercase files`, so a Windows window on a Linux server shows and sends `/` and a Mac on a Windows server shows `\`.
- **Inside, a relative path is this machine's `PathBuf`**: the tree joins its folders with `Path::join` (so its rows hold `src\lib` on Windows; the tree draws names, never that text), and a Windows server's relative paths (its search results, a link's `relative`) have their `\` made `/` as they come in (`Style::relative`), so on a Mac their parts are still parts and opening one opens its folders in the tree. The disk's own index keeps `/`, as before.
- **What the panel shows uses the root's separator**: the viewer's title (`Style::shown`, by parts), the folders of search results and of the finder's rows (`Style::in_form`, which keeps the lit ranges, since `/` and `\` are one byte each), the card's folder and the tree header's name. A file's full path is the root and its parts joined with the root's separator (`Style::join`), so on Windows it reads `C:\proj\src\x.rs` rather than `C:\proj\src/x.rs`.
- Checked only by unit tests on macOS (and the tree's test by the Windows runner); the panel itself was not driven on Windows or through a Windows server.

## Opening elsewhere (`open.rs`)

- **cornercase leaves opening in other apps to each window on purpose** (its `design/opening-in-other-apps.md`: "No request"): only the window knows the apps of the machine it runs on. Detection and command lines follow that design.
- Openers, in a fixed order: the file manager (Finder on macOS), then VS Code, Cursor, Zed and Sublime Text (their command on the `PATH`, which takes `FILE:LINE`, else on macOS their bundle in an Applications folder through `open -a`, which takes no line), then the default app. VS Code and Cursor need `-g` for the line.
- Finder reveals a file and opens a folder, but reveals bundle-like folders (`.app`, `.xcodeproj`…), which `open` would launch.
- The default app takes plain files only, never folders or programs; the menu checks this with one `stat` per entry.
- **How a path reaches the desktop is one shared helper** (`desktop.rs`), also used by the sidebar's folder entry, the peek card's default app, the Flows sheet's buttons that open a flow's file or a run's folder (gpui's `open_with_system` until 2026-11-04, which on Linux logs a failure and says nothing) and ⌘-click on a path (`design/terminal.md`): `open` and `open -R` on macOS; on Linux `xdg-open` (else `gio open`) for the default app, and for the file manager the freedesktop `org.freedesktop.FileManager1` D-Bus call (`ShowItems` selects a file in its folder, `ShowFolders` opens a folder; through `gdbus`, else `dbus-send`), which GNOME Files, Dolphin, Nemo, Thunar and Caja answer; when no tool or no file manager answers, `xdg-open` opens the folder. The URI is percent-encoded, with `'`, `,` and `\` escaped too, so a name can neither close `gdbus`'s quotes nor split `dbus-send`'s array. Every tool is found on the `PATH`, and a missing one is an error toast that says what to install (xdg-utils).
- **A launch waits at most 8 s** (`desktop::run`): a tool that answers within that time gives its success, or its failure with its last line on standard error (kept in an unlinked temporary file, not a pipe, so an app the tool leaves running can never block on it or die of a closed pipe; the file is made new with mode 0600, never opened over one already there, since `/tmp` is shared on Linux); one still running after that counts as launched and is reaped on a thread of its own, blocked in `wait` (a single reaper polling every such child was rejected: it trades idle threads for a wake-up that lasts as long as any app opened from here stays open, and only `xdg-open` outside a desktop leaves one). **The file manager's D-Bus call is a call, not a launch**: on Linux it waits for its answer, which `gdbus` and `dbus-send` give within the bus's 25 s reply timeout, and one still unanswered after 30 s is ended and counts as failed, so the folder fallback runs either way. Until 2026-11-04 a call past 8 s counted as launched and its later failure was lost, skipping the fallback (CodeRabbit's review). Rejected: a limit under the bus's, which would also open the folder when a file manager that starts slowly then shows the item, two windows for one click. `xdg-open` outside a known desktop (a bare window manager) runs the app in the foreground, so waiting for its exit would keep the job in the status bar until the app closes. Before 2026-11-04 the menu waited for the exit with no limit and said only the exit status.
- **Linux labels**: "Show in file manager" for a file and "Open in file manager" for a folder (the macOS menu keeps "Reveal in Finder" and "Open in Finder"). "Open in Files" was rejected: GNOME's file manager is called Files, but so is this panel, and KDE's is Dolphin.
- **Editors on Linux** are also found under their other names (Arch's `zeditor` for Zed) and as Flatpak exports (`com.visualstudio.code`, `dev.zed.Zed`, `com.sublimetext.three`, in `~/.local/share/flatpak/exports/bin` and `/var/lib/flatpak/exports/bin`) and snaps (`/snap/bin`, which a desktop session started without a login shell may leave off the `PATH`); all take `FILE:LINE` as their command does. Only editors are looked for there: the desktop's own tools (`xdg-open`, `gio`, `gdbus`, `dbus-send`) count only on the `PATH`, where `desktop.rs` runs them from, so the menu never offers a file manager or a default app that would then fail as missing (until 2026-11-04 they were detected in those folders too).
- Rejected: gpui's `reveal_path` and `open_with_system`. On Linux they ask the desktop portal, then fall back to `xdg-open` on the folder, and only log a failure, so a machine without them would open nothing and say nothing; ours selects the file through `FileManager1` and toasts. The portal's activation token, which helps a browser come forward on Wayland, matters less for a file manager; web addresses still go through gpui (`design/terminal.md`).
- **Checked live on Linux** on 2026-11-04 (Debian 13 arm64 in a container, Xvfb and openbox, gpui 0.2.2, cornercase 0.12.280, the debug build of this branch), with logging stubs of `xdg-open`, `notify-send` and `paplay` first on the `PATH` and a logging wrapper around the real `gdbus` (GLib 2.84): the sidebar's "Open in file manager" on a project ran `gdbus call … FileManager1.ShowFolders ['file:///tmp/demo'] ''`, which failed (no file manager on that bus), then `xdg-open /tmp/demo`; the Files menu showed "Show in file manager" and "Open with default app" (no editor installed), the first ran `ShowItems ['file:///tmp/demo/main.rs']` then `xdg-open /tmp/demo`, the second `xdg-open /tmp/demo/paths.txt`; with a `PATH` holding only `cornercase`, the sidebar entry gave the error toast naming xdg-utils. Not checked live: a real file manager answering `FileManager1` (GNOME, KDE), `dbus-send` (only `gdbus` was there), Flatpak and snap editors, a Wayland session, and macOS after the move to `desktop.rs` (unit tests only; its command lines are unchanged). Again on 2026-11-04, with a `gdbus` stub that fails after 10 s: "Open in file manager" showed its job in the status bar, then ran `xdg-open /tmp/demo` when the call failed; with one that never answers, the call was ended at 30 s and `xdg-open` ran then.

## Through the command line (`source.rs`, `served.rs`)

- **One `Source` per workspace, picked once**: `Disk(root)` on this Mac, `Server(workspace)` when the window drives another machine's server (`cli::host()` when the panel is built; switching servers builds a new panel). The tree, the viewer and the search ask the source and do not know which it is; their state, polling and dropping of stale answers stay the same.
  - Rejected: `cornercase files` on this Mac too. The disk is the documented exception (#345 upstream), and a process per read and per check costs more than a `stat`.
- **The tree**: one `files list ./A ./B … --workspace W --json` for all the open folders, answered in the order asked (the answer echoes each argument, so it is zipped with the request rather than matched by path). Entries are sorted here as on disk; `kind` `folder` is a folder (a link to one too), `more` is "some were left out". A folder's `error` fails that folder alone; a command that fails (ssh down) fails every folder with its reason, so the root shows why. `list` exits 3 when a folder fails and `read` 1 for a folder or a missing file, both with the JSON on standard output, which the CLI documents, so the answer is read whenever standard output holds an object.
- **Paths go after `--` and start with `./`**: a name starting with `-` would read as an option and one starting with `~/` as the server's home folder. The root is `.`. The parts are joined with `/` whatever this machine's separator, which a Windows server reads too, and an absolute path (a file outside the workspace) goes as its server wrote it, judged by its form (`paths::rooted`, `design/remote.md`): until 2026-11-04 a Windows window sent `/home/me/x` as `.//home/me/x` and a Mac sent `C:\x` as `./C:\x`, both relative to the workspace. A file's stamp asks its folder by the same rules (`served::folder_and_name`), so `C:\x\y.rs` is listed in `C:\x`.
- **The viewer**: `files read ./P --json`, or the absolute path as it is for a file outside the workspace (the CLI takes either). Text and images go through the same `classify` as the disk (an image's bytes are `image.data` in base64), so an SVG, which the CLI answers as text, still shows as an image. `binary`, `too-large`, `folder` and `missing` map to the viewer's notes; the limits (8 MB of text, 32 MB of an image) are the server's and the same as here. The grammar is still picked here from the name and first line, not from the answer's `language`, so a file colours alike on both sides.
- **Checking the open file**: every second `files list` of its folder gives its `bytes` and `modified` (UTC, to the millisecond, parsed into a `SystemTime` so the disk's `Stamp` serves both); only a change reads the file again. The open folders are listed every second check, as on disk.
  - Rejected for now: `files list --follow` and `files read --follow`, which push changes from the server. A connection follows one thing at a time, so the tree needs a stream per set of open folders, restarted on every expand, plus one for the file; polling keeps one code path for both sources and a closed panel still costs nothing. Worth revisiting if the round trips show on a slow link.
- **The search**: `files search -- Q --names|--text --json`, ranked and capped by the server as the disk search is here (200 names, 1,000 matches). Its `indices` and `ranges` count characters, so they become byte ranges here; a tab becomes one space, which keeps them in place. A search over ssh cannot be cancelled: a newer query only drops the older answer. A failed search says so in the summary line (`Results::Failed`).
- **The menu**: the openers launch apps of this Mac, so on another machine they are gone (and not even detected); "Copy path" (the path there) and "Copy relative path" stay.
- **Checked live** on 2026-10-29 with cornercase 0.12.225: the JSON of `list`, `read` (text, image, binary, too large, folder, missing) and `search` (names, text, non-ASCII lines), the exit codes, `--` and `./` paths, against a throwaway project on this Mac; the answers are the fixtures in `tests/fixtures/files/`. Through ssh (the local sshd and isolated server of `design/remote.md`) the panel listed the shown workspace's tree; the viewer, the search and the menu were not driven there.
- **Open with is a job** until the app it opens answers, so the status bar says so if it takes a moment.
