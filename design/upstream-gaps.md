# Upstream gaps

Code: every panel; `tools/cornercase-cli.sh` and what it makes, `docs/cornercase-cli.txt`

- **No workarounds**: this app is one more client of cornercase's documented command line. Scraping text output, reading cornercase's private files or reimplementing server logic would break on any cornercase release and hide the gap from other clients. A missing command, field, `--json` or stream is filed upstream, and the UI says what waits ("needs usecornercase/cornercase-terminal#123"), matched where possible by a stable field rather than by error text.
- **The Files panel reads the disk itself** (#345 upstream): a file viewer through the command line would copy every file through a process; cornercase documents this exception for external UIs.
- **Reading upstream** (#108): the flows and routines work in worktrees under `~/.cornercase/worktrees/cornercase-gpui/<branch>`, where a path relative to the checkout names nothing, so `AGENTS.md` gives a command that finds the clone from the main checkout and from any worktree, however it was made. The clone's checkout is whatever was pulled last, hence `origin/main` after a fetch. Rejected: a setup step that links the clone beside each new worktree, which covers cornercase's worktrees only, not one made by hand elsewhere.
- **Its help** is `docs/cornercase-cli.txt`, made by `tools/cornercase-cli.sh`: the first line is `cornercase --version`, then `cornercase <command> --help` for every command and subcommand, depth first, in the order of `cornercase --help` and without clap's `help`. The help is the same whatever the terminal's width (checked on 0.13.32 through a pipe and in a 60-column terminal), so the file does not depend on who makes it. Before 2026-11-10 nothing said how the file was made or from which release; the script remade the 0.13.31 file byte for byte below its first lines.
- **Filing an issue**: only for generic gaps or bugs (something any client would hit). Search first (`gh issue list --repo usecornercase/cornercase-terminal --state all --search "<keywords>"`). Follow the repository's templates (its `.github/ISSUE_TEMPLATE/`, read as `AGENTS.md` says): a bug (`--label bug`) has `### What happened`, `### Steps to reproduce`, `### Commit`, `### System`, `### Outer terminal` (none: a GUI client driving cornercase through its CLI), `### server.log` and `### Anything else`; a feature (`--label enhancement`) has `### Problem`, `### Idea` (in cornercase's terms: a command, a `--json` field, a stream; reference #345) and `### Alternatives`. In English, concrete, with a reproduction from the shell.
- **A stopgap kept until a fix lands** is listed under "To remove once these land" below, with its files, and removed when the release that fixes it is the one the app needs. The README stays about using the app, so this list for maintainers lives here (moved on 2026-10-31).

## What the window cannot do because cornercase lacks it

Filed from 2026-11-07 against cornercase 0.13.19, each with its reproduction from a shell. The window has no way round them. A muted line says what waits where a person would look, and gives way to the control when the command lands; a bullet with no such line says why.

- **The terminal's selection colour** (not filed yet): cornercase draws a selection as `inverse` cells in the `surface` frames, so a window cannot tell selected cells from a program's inverse text and cannot draw the selection in its theme's colour. The ask: mark selected cells apart from `inverse` in `surface`. The Appearance page's Terminal group says so in a muted line (`design/theme.md`).
- **Notices with no token** (#700): `cornercase notify`, a flow waiting for consent, a failed setup, and the queue's and routines' notices reach only an attached cornercase window, so a person who uses only this one is never told, and `notify` still exits 0. No line says so, since nothing arrives to say it on (`design/notifications.md`).
- **Following a wrapped address** (#701): `surface` does not mark the rows that go on in the next one, so a long address that wraps, as narrowing a pane can make it, is underlined and opens cut at the row's end. No line says so, since it would sit on every address (`design/terminal.md`, Paths and web addresses).
- **Logging in an account that exists** (#702): there is no `account login`, so a signed-out row has no button to log it back in. A muted line under the row names the issue, and its tooltip says how by hand (`design/accounts.md`).
- **Managing another machine's plugins** (#703): the `plugin` commands that act on files refuse `--remote`, so there the Plugins sheet has no switches, no install, update or remove, and no logs. Its note names the issue (`design/plugins.md`).
- **Knowing what each agent can do** (#704): no field says which agents cornercase can read, or which models and efforts each takes. A routine's cleanup box stays clickable and an agent that cannot do it is refused on saving, and the flow editor's agent, model and effort are typed. Muted lines under that box and under the orchestrator's fields name the issue (`design/queue.md`, `design/flows.md`).
- **Offering the machines a window reached** (#705): no command lists them, so a `me@10.0.0.5` reached from cornercase's own window has to be typed again in the ⇧⌘K dialog, which names the issue (`design/remote.md`).
- **Sending a held message without the half-written line** (#708): `held --send-now` submits what the person typed with it. The pane's band says so in a faint line and a tooltip (`design/terminal.md`, Drawing).
- **Checked live on 2026-11-07** with cornercase 0.13.19, Linux x86_64 under Xvfb with lavapipe, a fake `ssh` between two servers on one box (no real sshd, no macOS, no Windows): the lines for #702 (a fake agent answering `auth status` as signed out), #703 (a window moved to the other server through the dialog), #704 and #705 where they show. #708's and #709's are recorded in their files. #700 and #701 draw nothing. #723 and #729 are in `design/machines.md`.
