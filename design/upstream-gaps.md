# Upstream gaps

Code: every panel

- **No workarounds**: this app is one more client of cornercase's documented command line. Scraping text output, reading cornercase's private files or reimplementing server logic would break on any cornercase release and hide the gap from other clients. A missing command, field, `--json` or stream is filed upstream, and the UI says what waits ("needs usecornercase/cornercase-terminal#123"), matched where possible by a stable field rather than by error text.
- **The Files panel reads the disk itself** (#345 upstream): a file viewer through the command line would copy every file through a process; cornercase documents this exception for external UIs.
- **Filing an issue**: only for generic gaps or bugs (something any client would hit). Search first (`gh issue list --repo usecornercase/cornercase-terminal --state all --search "<keywords>"`). Follow the repository's templates in `../cornercase-terminal/.github/ISSUE_TEMPLATE/`: a bug (`--label bug`) has `### What happened`, `### Steps to reproduce`, `### Commit`, `### System`, `### Outer terminal` (none: a GUI client driving cornercase through its CLI), `### server.log` and `### Anything else`; a feature (`--label enhancement`) has `### Problem`, `### Idea` (in cornercase's terms: a command, a `--json` field, a stream; reference #345) and `### Alternatives`. In English, concrete, with a reproduction from the shell.
- **A stopgap kept until a fix lands** is listed under "To remove once these land" below, with its files, and removed when the release that fixes it is the one the app needs. The README stays about using the app, so this list for maintainers lives here (moved on 2026-10-31).
- **Where it stands** (2026-11-02): every issue filed so far has landed (#456, #461–#472, #475–#480, #567 in cornercase 0.12.237: a pull request's checks one by one, asked for again as the dialog opens, `design/pull-requests.md`, and #573 in 0.12.239: a flow started on an issue with an edited task keeps the issue's workspace name, `design/flows.md`) except #549 and #583 (`flow run --focus --view` moves cornercase's window, not the view, `design/flows.md`). #665 is open: an account added by a command reaches no stream, so the window lists the accounts when something else tells it to (`design/accounts.md`). #584 is open: a merged pull request shows only at the server's next read, up to a minute later, or 5 minutes after a failed read (`design/pull-requests.md`); the window needs no change once it lands, so nothing waits on it here. Managing plugins on another machine waits on commands cornercase does not have yet, and the UI says so (`design/plugins.md`), as it does for what is under "What only cornercase's own window can do" below. #664 (2026-11-06) asks `status --json` and `view` to name a pane's conversation: until then a Recap link whose conversation moved to another pane shows its workspace, and the toast says so (`design/recap.md`). #668 (2026-11-06) asks for the Discord forum's servers and a command to pick one: until then Settings says that step takes cornercase's own window (`design/settings.md`). #675 (2026-11-06) asks `stats --cached`: until then the first read of a machine's stats in the Usage sheet waits for the ask, and its spinner says so (`design/usage.md`). #666 (2026-11-06) asks `plugin run` for a `--view`: until then a plugin's button acts on what cornercase's own window shows and a popup needs that window attached, and the slot's tooltip, the Plugins sheet and the refused popup's toast say so (`design/plugins.md`). #678 (2026-11-06) asks `cornercase clone` for the `files` its request takes: until then the Clone form copies no git-ignored files and says so in a muted line (`design/machines.md`). #679 (2026-11-06) asks `start` for a `--placed`: until then the window finds a new tab on a machine by comparing the project's tabs while the agent holds its answer (`design/machines.md`).

## What only cornercase's own window can do

Filed on 2026-11-06, against cornercase 0.13.1. For each, `--help`, `contract --json`, upstream's `CHANGELOG.md`, `design/` and sources were read and the shell was tried on a server of its own, so each issue carries its reproduction. The window has no way round them: a muted line says what waits where a person would look for the TUI's control, and gives way to the control when the command lands.

- **Pairing a phone's browser** (#669; the TUI's since 0.12.37): `config set remote` only turns the listener on. The single-use code is made when the TUI's dialog opens and dropped when it closes, so there is nothing to draw a QR code from. The paired browsers' row in Settings › Remote says so (`design/settings.md`).
- **Pairing a Telegram or Discord chat** (#670; 0.12.83): the same dialog, and Discord's owner is asked for only while it is open. The phone rows of Settings › Remote say so. One command can answer #669 and #670; they are two issues because what each one needs differs (Tailscale and the listener, a bot and its owner).
- **Removing a closed project's worktree or a leftover, and deleting a branch** (#671; 0.12.163): `close --remove-worktree` needs an open workspace and keeps the branch. Rejected: `git worktree remove` and `git branch -D` from here, which skip the teardown, the second look and the rules on which branch goes. The Worktrees sheet's foot and both Remove questions say so (`design/worktrees.md`).
- **Run setup** (#672; 0.12.108). Rejected: typing the script with `new-tab`, tried live: `CORNERCASE_WORKTREE` was empty in it and the workspace stayed `setup failed`. A worktree's menu says so (`design/sidebar.md`).
- **Importing a VS Code workspace** (#673; 0.12.0): `open` answers that the file is not a folder. Rejected: reading the file here and calling `group new`, `open`, `move` and `rename`, which copies `project/vscode.rs` and, on another machine, needs a file there. The Projects `+` says so (`design/sidebar.md`).
- **A plugin's window processes** (#674; 0.12.115): only cornercase's own client starts them. Tried live, none ran with the server alone or with a `view` attached, and one ran while its window was attached. Rejected: running them here, which copies the supervisor and the files `plugin remove` reads. The plugin's card says so (`design/plugins.md`).
- **Checked live on 2026-11-06** with cornercase 0.13.1, on Linux x86_64 under Xvfb with lavapipe, on a server of its own: every line above where it shows. Not checked: macOS and Windows (nothing here depends on the platform), and a real tailnet or bot, so the pairing rows were only seen unpaired.
