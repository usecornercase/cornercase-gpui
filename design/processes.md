# Processes

Code: `src/panels/processes.rs`, `src/panels/processes/`, `src/panels/poll.rs`

- **The TUI's Processes dialog as a sheet** (⇧⌘M, the rail's pulse icon; ⇧⌘P until 2026-10-31, when it went to the file finder): every pane with what runs under its shell, the CPU and memory of each process and the pane's sums, then cornercase's own line (the server, plugin services, its git jobs), from `processes --json`. A runaway dev server or an agent's leftover build is found here instead of in `top`, with the pane it belongs to.
- **It is sampled every 2 s while the sheet is open, never two at once** (`poll::Watch`): `processes` has no `--follow`, and each sample waits its own `--interval` (1 s), so a sample is one short process. Opening the sheet samples at once; a closed sheet asks nothing. A stream would be lighter, noted for upstream.
- **A table of cards** (asked for on 2026-10-31, to improve the sheet's look): the filter and the scope stay at the top, the column names (Pane, PID, CPU, Memory) under them, and the totals in a footer, each under its column; only the panes scroll (`processes/columns.rs` holds the widths all three share). Until then no figure was labelled, and the totals were a faint line that scrolled away with the toolbar. Tiles of the totals above the list were rejected: a sum reads best under what it adds up, and the toolbar stays one row.
- **The pane's row stands for its shell**: it shows the shell's pid and the pane's sums, and the tree under it starts with the programs the shell runs, so a pane running only its shell is one line. A `zsh` row under a `zsh` heading filled half the sheet with nothing to act on, since the shell has no Stop. The row names the agent, else the program, after an icon (a bot for an agent, a terminal otherwise), then the place as the TUI writes it: `project › workspace › tab`, with `· pane N` only when the tab is split.
- **The order is the sidebar's by default**, as `--json` gives it; the CPU and Memory column names sort the panes, busiest first, and Pane goes back. A sortable table is sorted from its header on macOS (Activity Monitor, Finder); the segments it replaced took room in the toolbar. Processes inside a pane keep the tree order the command gives, indented by their depth, which is worked out from `parent`, with a faint guide per level.
- **While the pointer is over the list, the order holds**, as in the TUI: figures change in place, new panes go last, gone ones leave, and the order catches up once the pointer leaves. Sorted by CPU, rows otherwise trade places every 2 s under the pointer, and with them the Stop it is about to press. The hold belongs to one opening of the sheet (`Watch::opening`): closing it with the pointer over the list (Go, ⇧⌘M) sends no leave.
- **A pane is folded to the programs its shell runs and to whatever uses 5 % of a core or more**, with the processes between that one and the shell; "Show N more" opens the rest, as does the chevron. An agent's pane otherwise fills the sheet with its compilers and shells; folding by depth alone hid what the sheet is for: on 2026-10-31 a busy loop in a subshell sat at 99.9 % behind "2 more", its pane at 99.9 % and every row shown at 0.
- **The filter matches the place, the program or any command line**, as the TUI's does. A pane found through its processes shows those and the ones above them, folded otherwise the same way; cornercase's own line is left out while it filters. Escape clears it, then closes the sheet.
- **CPU reads by its colour**: a figure that shows 0.0 is faint, so the busy ones stand out, and from half a core it is orange (the site's waiting colour, as Usage marks a limit near its end) and semibold; a pane's row adds a meter of one core, drawn only while the pane uses some. Memory has no colour: no amount is too much for every program.
- **Go and Stop show on the row under the pointer**, as the TUI shows its buttons on the hovered row, so seven panes do not show seven Go and every program a Stop; a stopping row keeps its spinner.
- **A process is named by the program in its first argument**, falling back to `name`: Claude Code reports its version as its process name. The row and the stop confirmation name it alike. Long command lines end in "…" at their column's edge (`design/widgets.md`), and line breaks and tabs in arguments read as spaces.
- **Every pane or this workspace**: the second passes `--workspace`, and cornercase then leaves its own line out. Switching drops a sample that answers for the other scope. Segments replaced a checkbox, as Ports chooses its scope.
- **Stopping asks first** (`dialogs::confirm`) and sends `processes stop PID --started S`, so a pid reused since the sample is refused. The pane's shell has no Stop (close the pane instead) and nor does cornercase's own line, as in the TUI. The command waits up to 3 s, so it runs beside the queue (`poll::confirm_stop`); meanwhile the row dims and a spinner takes the button's place, and it keeps it until a sample begun after the stop answers (`poll::Stopped`), so the row never shows Stop again before it goes.
- **Go** focuses the pane and closes the sheet.
