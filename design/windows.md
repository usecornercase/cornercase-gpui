# Windows

Code: `.cargo/config.toml`, `Cargo.toml` (the `windows` crate's features, gpui without `windows-manifest`, `embed-resource`), `build.rs`, `assets/windows/`, `tools/icon.py`, `platform.rs` (`Os::Windows`, `command`), `platform/paths.rs`, `main.rs` (`windows_subsystem`, `fail`), the `win32.rs` modules with their `no_win32.rs` twins (`desktop/`, `notify/alert/`, `panels/browser/`, and `panels/files/peek/shell.rs`), `.gitattributes`, `.github/workflows/ci.yml` (the Windows job); each area's Windows behaviour is in its own file

- **Windows is a third platform of the same app, not a port** (asked for on 2026-11-04, once cornercase itself ran natively on Windows, its 0.12.287): one code base, the same commands and the same look, with Windows' conventions where Linux's or a Mac's would be wrong there. gpui 0.2.2 draws on Windows through DirectX 11 and DirectWrite, and falls back to WARP, Windows' software renderer, where there is no GPU (the CI runner has none). macOS and Linux did not change, except where a rule found on the way was wrong everywhere (a path shortened to `~` without a folder boundary, the first window larger than a small screen).
- **Platform code is plain logic that takes the platform**, as for Linux (`design/linux.md`): what differs is a function of `Os`, tested for all three on any host. `#[cfg(windows)]` holds only what cannot compile elsewhere, the Win32 and WinRT calls, each in a `win32.rs` beside the module that needs it, with a `no_win32.rs` of the same functions elsewhere (declared through `#[path]`, as `peek/no_player.rs`), so callers compile unchanged. They use the `windows` crate at 0.61.3, the version gpui 0.2.2 already pulls, so no other crate comes in; its features are listed once in `Cargo.toml`.
- **Every child process starts without a console window** (`platform::command`, clippy's `disallowed-methods` refuses `Command::new` elsewhere). The binary is a GUI program (`#![windows_subsystem = "windows"]`, outside tests), so it has no console, and Windows gives each console program it starts (`cornercase`, `git`, `ssh`) a new console with a window of its own: one would flash for every command. `CREATE_NO_WINDOW` gives the child a console without a window, which the programs it starts share. Rejected, as cornercase rejected it for its server (its `design/windows/server.md`): `DETACHED_PROCESS`, which leaves the child no console, so every console program it starts in turn would open a window. Checked on Windows (below): the window ran its commands and nothing flashed.
- **What is the user's own**: the home folder is `std::env::home_dir` (`desktop::home`), `USERPROFILE` on Windows, where `HOME` is not set (it was read in eight places); the window's settings and the browser's profile live under `%LOCALAPPDATA%` (`prefs.rs`, `design/browser.md`); temporary files need no mode, since `%TEMP%` is the user's own (`design/files-panel.md`).
- **Areas**, each in its file:
  - The window: Windows draws the frame and the app the title bar, whose empty ground and buttons are marked for Windows' own hit test (moving, snapping, maximising, Snap Layouts on the maximise button; the window menu does not open, a known limit); the buttons look like Windows'; the ground is the Mac's glass over Windows 11's acrylic, opaque where there is none; the exe's icon, manifest and version; errors before the window in a message box; the first window fits the screen (`design/window.md`, Windows; `design/widgets.md`, the ground).
  - Keys: Linux's scheme, Alt+F4 left to Windows, AltGr that Windows reports as Ctrl+Alt (`design/terminal.md`, Keys on Windows).
  - Fonts: Cascadia Mono, else Consolas, Lucida Console or Courier New, for the terminal, and Segoe UI for the chrome (`theme/fonts.rs`, `design/widgets.md`, Fonts).
  - Paths: whose rules a path follows (a server's, git's or this machine's), `~` (`design/remote.md`; `design/files-panel.md`, Paths on Windows and across machines).
  - Opening a path with its default app and in File Explorer through the shell, programs found through `PATHEXT`, the refusal of programs (`design/files-panel.md`, Opening elsewhere).
  - Previews from the shell's thumbnails (`design/files-panel.md`, Peeking at a path).
  - Desktop notifications as toasts and sounds through `PlaySoundW` (`design/notifications.md`, On Windows).
  - The Browser panel: Edge out of the box, the profile, attaching to and ending the browser, keys, downloads, ssh tunnels with Windows' OpenSSH (`design/browser.md`, Windows).
- **Finding cornercase**: the `PATH`, then `~\.local\bin` (the PowerShell installer's) and `~\.cargo\bin`; no login shell; the registry's user `PATH` is not read (`design/connection.md`). An explicit `.exe` path is a program even when `PATHEXT` leaves `.exe` out (the search on the `PATH` still follows `PATHEXT`). The minimum is 0.12.287, its first release here. `locate.rs`'s `unix_dirs`, `merged` and `shell_args` are plain logic compiled on every platform (nothing calls them there, since `asks_login_shell` is false). The missing page was not seen on Windows; CI's clippy and tests cover the lookup.
- **Building**: Visual Studio's Build Tools with the C++ workload (MSVC and the Windows SDK), as any Rust program for `x86_64-pc-windows-msvc`. A release build compiles gpui's HLSL shaders with the SDK's `fxc.exe` (`GPUI_FXC_PATH` names it when gpui does not find it), and so needs a Windows host; a debug build compiles them when the window starts. Releases ship a zip (`design/releases.md`); there is no installer yet (#24), so the README shows a Start menu shortcut made by hand. **The C runtime is linked statically** (`-C target-feature=+crt-static` in `.cargo/config.toml`, for every build, as Zed does), so the exe runs on a Windows without the Visual C++ redistributable instead of dying before `main`; never set `RUSTFLAGS`, which replaces it. Windows on Arm is not built; the x64 binary runs there under emulation, as cornercase's does.
- **Checking it from a Mac**: `cargo xwin` (cargo-xwin 0.21, with LLVM 20's `clang-cl`, `llvm-lib` and `llvm-rc` on the `PATH`) brings Microsoft's CRT and SDK, so `cargo xwin clippy --target x86_64-pc-windows-msvc --all-targets --all-features --locked --target-dir target/win -- -D warnings` checks the Windows code, and `cargo xwin build` links a debug exe whose resources `llvm-readobj --coff-resources` lists. Running needs Windows: CI's job runs clippy and the tests there.
- **CI** (`.github/workflows/ci.yml`): a `clippy + tests (Windows)` job on `windows-2025` runs the same `cargo clippy` and `cargo test` as the macOS and Linux jobs. The repository's text files are LF on every checkout (`.gitattributes`, `* text=auto eol=lf`), since the runner checks out with `core.autocrlf=true` and the fixtures are compared byte for byte, as cornercase found (its `design/windows/tests-and-ci.md`). Tests that need Unix (a `/bin/sh` fake, file modes, `/dev/zero`, a path that is not UTF-8) are `#[cfg(unix)]`, with a Windows twin where the rule has one; logic tests whose only problem was a `/` in an expected path build it with `Path::join`. The first run on Windows found 19 of 1,224 failing, all such tests.
- **Checked on Windows** (2026-11-04, GitHub's `windows-2025` runner: Windows Server 2025 Datacenter, build 26100, no GPU; a debug build; cornercase 0.12.287 from its installer; a manual run of CI's `smoke (Windows)` job, `.github/smoke/windows.ps1`, which sends keys with `SendKeys`, moves and presses the mouse with `SetCursorPos` and `mouse_event`, reads the window's state with `DwmGetWindowAttribute` and `IsZoomed`, and keeps screenshots of the screen): the window started cornercase's server and opened on the project asked for, drew the rail, the sidebar, its cards and a PowerShell 7 pane at its prompt, with the mark in the taskbar; typed lines ran (`echo`, `dir src` with its colours); Ctrl+Alt+Shift+E, C and B opened Files (the tree of `C:\demo`), Changes (the modified `README.md`) and the Browser (Chrome found and started headless, its start page drawn); Ctrl+Shift+/ showed the keys as Windows spells them; Ctrl+Shift+T opened a tab and Alt+1 went back; Ctrl+Shift+, opened Settings; resting the pointer on `C:\demo\notes.txt` printed in the pane drew its card, and Ctrl+click opened it in Notepad; the title bar's buttons maximised, restored and minimised the window, a double press on its ground maximised and restored it, and a drag moved it; Alt+F4 quit with status 0 and left no `chrome.exe`; no console window opened for any child. All 1,316 unit tests and `tests/layers.rs` pass there. **Known limits found there**: the window menu opens neither from a right press on the title bar nor from Alt+Space (`design/window.md`, `design/terminal.md`). Not checked: a real GPU, a HiDPI screen, Windows 10 and 11 themselves (the runner is Windows Server), Windows on Arm, a non-English keyboard layout and AltGr, toasts and sounds (no agent finished there), the shell's thumbnails, `--remote` through Windows' `ssh.exe`, and a person's eyes and hands on it.
- **The smoke run stays** (`smoke (Windows)` in `ci.yml`, only on a manual `workflow_dispatch`): with no Windows machine at hand it is how a change to the window is seen on Windows; it installs cornercase's latest release, builds the debug exe, runs `.github/smoke/windows.ps1` and uploads its screenshots and notes as the `smoke-windows` artifact. Its clicks are placed from the window's bounds and the title row's height, so a change to the title bar's layout moves them. It never runs on a pull request or a push.
