# Accounts

Code: `src/panels/accounts.rs`, `src/panels/accounts/`; for the panes, see The account of a running pane below

- **What the sheet covers**: the accounts agents log in with (`cornercase account`) and profiles (`cornercase profile`). One card per agent that takes accounts: its own login and each account, whether it is signed in, which is the default, names, adding (and logging in, in a tab of that account) and removing. Profiles, a tool for scripts, come after, in a card of the same shape.
- **Where the code is**: `accounts.rs` holds the state, loading, the changes, the top of the page and what both kinds of card share (the rename row, a form's buttons and note); `accounts/agents.rs` an agent's card, its rows and the add form; `accounts/profiles.rs` the profiles card; `accounts/widgets.rs` the sheet's own pieces (cards, rows, the radio, forms), which the Machines sheet shares (`design/machines.md`); its chips, status dot, row actions and callouts are `ui/signs.rs`, shared with Settings since 2026-10-31; `accounts/data.rs` the rows' texts and the commands, tested without a window; what `account list --json` answers is `model/accounts.rs` since the window reads it too.
- **The layout** (asked for on 2026-10-31: the sheet was "a visual mess"). The page repeated the sheet's title as a heading over a long sentence, each agent was an uppercase heading with its variable over a card, "Make default" showed only on the rows that were not the default and "Remove" only on accounts, so Rename and Remove moved from row to row, the logins ran on after the names in their colours, and every agent had an add form open, which on a machine without accounts was most of the sheet. Now, as in the Processes and Issues sheets:
  - The top is one muted line saying what an account is, beside a refresh icon that turns into a spinner while the list or the logins are being asked (the Issues sheet's), then the token warning when there is one.
  - Each agent is a card: a header (the agent's icon and name, its variable in the terminal's font, faint, and "Add account"), then a row for its own login and one per account.
  - Every row has the same columns: a radio, the name with its chips (`own login`, `default`) over the folder (a line ending in "…", the home folder as `~`), the login (Issues' status dot: green signed in, red signed out, orange when the check failed, a faint ring when unknown or not checked; the plan as a chip), and the actions in fixed slots, rename then remove. The own login cannot be removed, so its slot stays empty instead of letting the rename icon move. Files that are no longer shared show under the row, as an error does, so the row keeps its two lines and its radio and login stay centred on them.
  - Names are plain text: in a flex row beside the chips, `ui::one_line` drew nothing at all (its box had the name's width, but no text; seen live on 2026-10-31, not understood), and a name is at most 32 characters anyway.
  - **The default is a radio**: an agent always has exactly one, as the TUI's `●` says, and a radio is the control for one of many; pressing a hollow one runs `account use`. The `default` chip says it in words. Rejected: Flows' star (a toggle that clears, while an agent always has a default) and the old row of text buttons.
  - Rename and remove are faint icons with tooltips, always shown: an agent has few accounts, so hiding them until hover (as Processes does for dozens of panes) would only hide them.
  - **The add form opens from the header** and closes after adding, on Cancel or on Escape in its field (a form's field cancels, as a dialog's does, `design/terminal.md`); one form or one rename is open at a time. It shows the name's rule under the field, and its error in that place.
  - Rejected: a toolbar (nothing to filter), a footer (no totals), a column of agents beside a page (three agents fit one scroll).
- **The list first, the logins after**: `account list --check` asks each agent whether it is signed in and can take a while, so the sheet shows `account list` at once and then the checked list. While the check runs, the rows it answers for say "Checking the login…": every account, and the own login once the agent has an account, the only times cornercase checks it. A failed check leaves the list as it is: those rows say "Login not checked", with the reason as their tooltip, rather than nothing. A check that answers while a change runs is dropped: the change is newer and lists again itself.
- **After every change, list again**: a change that prints its own `--json` answer is shown at once, then `account list` runs again to bring the logins. One change runs at a time: meanwhile the other controls rest, dimmed but in place, so nothing moves and nothing is sent twice.
- **A change shows where it was asked** (`data::target` reads the row from the command): its row dims and its login column says what runs (`Making it the default…`, `data::doing`), or the form's button turns into a busy button; the status bar names it too. A failure shows under that row or in that form; one without a place shows at the top.
- **Logging in a new account**: `account add --login` opens the login tab in the workspace this window shows, and the sheet closes on that tab so the login can be done. "Log in now" can be turned off per agent. A signed-out row says in its tooltip how to log in again (the agent run in a tab of that account): cornercase has no command that logs an existing account in from a client, so the sheet offers none.
- **Names are checked before running**: `valid_name` mirrors what `account add` takes (letters, digits, `.`, `_` and `-`, at most 32, never `.` or `..`), so the form says why at once instead of showing cornercase's error. Every command puts names after `--`, so a name that starts with `-` is never read as an option.
- **Token variables win**: a token variable set in the server's environment wins over every account, so an orange callout says so above the agents. It stays above them, not in the agent's card: cornercase lists the variables, not which agent reads each, and telling it from the name here would be server knowledge.
- **Profiles**: a profile maps each agent to an account; an agent left out uses its own login. While a profile is in use it is the default, and making an account the default leaves it; "No profile" is `profile use --system`. Its radio says which is in use, each agent's account is a segment, and the rows show only once a profile exists ("New profile" opens the form).
- **Removing asks first, through `dialogs::confirm`** (AGENTS.md), instead of the red box that opened under the row: removing an account deletes its folder, and the question says that the keychain item stays (logging out is the agent's own command, in a tab of that account). Deleting a profile asks too.
- **Errors read as sentences**: `cli::reason` (shared with Settings) drops `cornercase account:` and `error:` from a failed command's message before it is shown.
- **Checked live** on 2026-10-31 with cornercase 0.12.230: the user's accounts (three agents, none with an account), and through a `CORNERCASE_BIN` wrapper that answered `account list` from fixtures and refused every change (so a change's busy row and its error could be seen without changing anything): accounts signed in, signed out and failed, a named own login, files no longer shared, one and two token variables, profiles with one in use, a slow check and a failed one with its tooltip, the add form (a name refused here, a refused add), a rename, the remove question, a radio pressed; at 1280 and 900 px wide.

## The account of a running pane

Code: `src/model/accounts.rs` (the list, `Session::accounts_stamp`, the mark, the switchers and what a switch says), `src/terminal/pane_accounts.rs` (the chips, the menu), `Store::list_accounts`, `Store::switch_account`.

- **Only once there is an account** (`AccountsInfo::any`, upstream's `has_accounts`): the mark, the chips and `Switch account` draw nothing until `account list --json` names an account, so nobody who never added one sees a change, not even a pane whose agent has a `CLAUDE_CONFIG_DIR` of its own (`custom`). Upstream pays the same cost. `account_mark` and `account_switcher` of `config --json` are followed like the sidebar's settings (`sidebar/look.rs`), on unless turned off; without chips the menus keep `Switch account`, so turning them off never loses the switch, as upstream's row does.
- **When the list is read**, never on a draw: when the window connects, when the Accounts sheet closes, when the window becomes active, and when a line of `view` changes `Session::accounts_stamp`, the config's revision and the accounts panes use. `account rename`, `use`, profiles and removing a named or default account change `config.json`, which the revision follows; a pane on an account not seen before brings one added elsewhere, as `account add --login`'s tab does. Only the answer to the latest question counts, so an older one cannot overwrite it. A switch that fails lists again too, since it may have named an account removed meanwhile. Limit (#665 upstream, seen on 0.13.1 with `view`, `status --follow`, `status --app --follow` and `events` running): `account add`, and removing an account with no label that is nobody's default, reach no stream, so an account added by a command and used by no pane shows when the window next becomes active. Upstream's window lists again when the folder's modification time changes, which a client must not read (`design/upstream-gaps.md`).
- **The mark** (`AccountsInfo::mark`) goes after the model in a tab's sidebar row, an agent's row and the tab bar: `claude · Opus 5.5 · Work · 12%`, `Opus 5.5 · Work · 12%`. It is the label, else the folder; `custom` as such; on an agent's own login that login's name or `System`, only while that agent has accounts. It reads the pane the model and context come from (`Tab::agent_pane`), so a line never mixes two panes. Upstream cuts the model first in a narrow column; these lines are `ui::one_line`, which end in "…" where their box ends, so the percentage goes first here. A row whose restart waits ends in `restarts after this turn`.
- **The switcher is a chip in the card's bottom padding**, right-aligned, 10 px in the terminal's font: `claude: Work ⌄`. Upstream gives every pane a row of its own under the terminal; this window draws floating cards with 12 px (`layout::PADDING`) around their cells, and that padding has room for one line of small text. So no pane loses a row, no PTY changes size when the first account is added, and no cell is ever covered: the chip takes 12 px, 1 px above the card's edge. Rejected: a row under each card (a row taken from every stacked pane, for what is in reach anyway); showing it only on hover, as the pane's handle does (the handle is for a rare action, while what account a pane spends is worth reading at a glance); the top padding (the handle's); a header (rejected for the handle too).
  - **Drawn in the canvas's prepaint, not as a child like the handle** (`pane_accounts::place`, `Placed::over`): `Layout` is computed in prepaint, after `render` ran, so an element placed in `render` would sit where the card was until the next redraw, while the chips always show. A chip is an ordinary element laid out as a root and painted after the panes, so its hover, tooltip and press work as usual; it hides while a pane moves, since the cards slide, and comes back when they rest.
  - **A press on a chip belongs to the chip**: it opens the menu of that pane, over the chip rather than at the pointer (`context_menu::above`, as upstream's does: snapped inside the window from the card's bottom, the last row sat under the pointer, lit), sends nothing to the program, starts no selection and leaves the focus (as upstream's row does). Along its width it wins over the 4 px of a divider's grip that reach into the card. A right click there is still the pane's menu.
  - **On a shell, one chip per agent with accounts, as upstream's row does**, naming what a `claude` typed there would get (`accounts` on the pane, else the own login): a shell is where the account of the next agent is decided, nothing else says it, and the padding has the room. It dims while something other than the prompt is in front (`at_prompt`), but stays pressable: the server refuses and says why. Choosing starts a new shell in that pane's place, which the server refuses too if a line is being typed.
  - **A pane running an agent without accounts shows none.** Upstream draws the other agents' buttons there, dimmed, because its row is there anyway; here a chip that can change nothing would only be noise.
  - **What fits** (`chip_texts`, upstream's `accounts_bar::pills`): `claude: Work` while all fit, then `Work`, then the last chips go, then one name cut with "…", then nothing below three characters. Counted in characters, since the font is the terminal's.
  - **Its tooltip** says where the pane runs and where new workspaces start, from `accounts` and `profile` of `status --app` (`Selection`, followed live): so a pane that differs from what new work gets can be told without opening the sheet.
- **Switching** (`Store::switch_account`, `Switch`): the menu has the own login, each account with a check on the current one, then Manage accounts…; a `custom` or removed account shows first, marked. Choosing runs `account restart --json --pane N [--system] -- AGENT [ACCOUNT]` beside the queue as a job, since the server answers only once the conversation has moved: the chip turns into a spinner with what runs once it has taken a moment (`Jobs::shown`, so a quick restart does not flash), the status bar names it, and a toast says what came back: `claude restarted on Work`, `claude restarts on Work after this turn`, or, for `skipped`, `claude did not move to Work: stop vim first` as an error, in the server's words.
  - **The server decides what can move.** Upstream disables the entries and notes why (`account_blocker`), which reads what only the server knows: a program in front, a draft, a setup. Copying those rules here would drift, so every entry stays live, and the answer says why. A flow's seats and `custom` come back the same way.
  - **A restart that waits for the turn** is in the pane's `account_restart`: its chip and rows say `restarts after this turn`, without the target, which the JSON does not give. The current account's entry then reads `Stay on Work`: asking for the account the pane runs on is how the server cancels (`skipped`, shown as `claude stays on Work`), and another account re-points it. Without a waiting restart that entry does nothing.
  - **The same list is `Switch account ›` in an agent's menus**: the tab's (its agent's pane, as the mark), the pane's and the agent row's, which share `agent_menu`. Only where the pane's agent has accounts: on a shell the chips are the way. It is a submenu rather than `Switch account…`, like Move pane: the `…` of the other entries promises a dialog. The check sits at the row's right end, since the rows share a menu with Manage accounts…, which has none.
  - **A chip has no tooltip while a menu is open**: gpui 0.2.2 keeps a tooltip that is still waiting to show through a press (only a move off the element cancels it) and shows it by the element's bounds whatever covers them, so half a second after the press it covered the menu's rows (seen live). An element that no longer has a tooltip drops it.
  - Machines' panes are left out, as are account pickers where agents start (a later change).
- **Checked live** on 2026-11-06 with cornercase 0.13.1, Linux x86_64 under Xvfb with lavapipe, private servers, and fake agents that print `CLAUDE_CONFIG_DIR`, an agent's chip and a shell's two: the switch seen in the fake agent's own line, the mark following in a tab's row, an agent's row and the tab bar; a label, `custom`, the own login's name; the menus of the chip, the pane and the tab; `restarted`, `waiting` with `Stay on…` cancelling it, `skipped` with the server's why (`stop sleep first`, `its account was not set by cornercase`); a restart held by a `CORNERCASE_BIN` wrapper, for the spinner and the status bar; chips narrowing over five panes; a pane moved from its menu, its chips landing with it; both settings off, the pane's menu keeping the switch; the sheet's closing bringing an account added by a command; and every account removed, which left no chip, no mark and no entry, in the same cells. Not checked: the window becoming active (no window manager under Xvfb), macOS, Windows, a real agent's conversation moving (the fake has none, so it starts fresh), a machine's panes.
