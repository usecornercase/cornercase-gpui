# Pull requests

Code: `src/model/pull_request.rs`, `src/dialogs/pull_request.rs`, `src/dialogs/pull_request/` (`signs.rs` the row's tags and the signs and colours of checks, `stack.rs` the stack section), the row's tags in `src/sidebar/workspace.rs`, `Store::ask_agent`

- **The TUI's pull request dialog, as a dialog** (cornercase's `design/pull-requests.md`; asked for on 2026-11-01, when the window only had the row's tag): a click on a workspace row's `#485✗` (or its stack mark), **Pull request #485…** in the row's menu, or ⌘P for the workspace on screen opens it, and ⌘P closes it again. It shows the title; the state, a conflict with the base and the checks' rollup as chips; the branch and its base; the stack; and the checks. Its buttons: **Ask agent** (only while it conflicts or a check failed), **Copy link**, **Done** and **Open on GitHub**, the default (Enter). Until then the tag opened the pull request in the browser, and the menu had a submenu with the title, Open in browser and Copy link.
  - **Opening it here**, where the TUI's default is to copy the link: the TUI's server may be on another machine and cannot open a browser on yours, while this window always runs on the Mac you look at, so the address opens here even with `--remote`.
  - **Ask agent is not offered once merged or closed**, unlike the TUI, which offers it for a merged pull request whose checks had failed: there is nothing left for the agent to fix.
- **Where it comes from**: only the session (`view`): each workspace's `pull_request` carries `number`, `title`, `url`, `state`, `checks` (the rollup: `failing`, `pending`, `passing`, or none), `failed` (the failed checks' names), `conflicts`, `base`, `provider` and `stack`. The dialog follows the session while it is open (a `Store` observer), so a check that finishes shows at once, and it closes itself when the pull request goes away (the branch changed, the setting was turned off), as the TUI's does. It closes only when the store still shows it, so a dialog still animating out cannot close the one opened after it.
- **What waits upstream** (usecornercase/cornercase-terminal#567, filed on 2026-11-01): every check one by one (the passed, pending and skipped ones, each with its workflow or GitLab stage and its link), the TUI's counts (`open · 1 failed, 3 passed`), and asking gh again the moment the dialog opens (the TUI lifts the project's wait; here the dialog shows what the last poll saw, up to a minute old). Running `gh pr view` from the window was rejected (`design/upstream-gaps.md`): it would redo the server's rules (which run of a check counts, GitLab's pipeline, which tool a host needs) and poll GitHub a second time. So the checks section lists the failed checks by name, or one line for the rollup (`Checks are running`, `Every check passed`, `No checks`), and a muted line names #567 (a click opens it). Ask agent pastes `pull request #485 has merge conflicts with main and failed its checks: test, clippy (https://github.com/…/pull/485) `, where the TUI gives each failed job's link: with the pull request's address the agent finds them (`gh pr checks`).
- **The row** (`dialogs::pull_tag`, `dialogs::stack_tag`): `#485` and the rollup's glyph in its colour (`✗` red, `•` yellow, `✓` green; muted without checks). An open or draft pull request that conflicts shows `#486!` in the waiting orange whatever its checks, as the TUI's (#359 upstream: GitHub runs no `pull_request` workflows while it conflicts, so the checks would read green). Merged takes GitHub's merged purple (`colours::merged`, xterm 99, the TUI's `MERGED_COLOR`) without a glyph; closed is faint and crossed out. In a stack, `2/3` follows (GitHub's position and size), muted, red when what blocks below is a failed check, orange when it is a conflict. Both open the dialog, and their tooltip gives the title, the summary (`open · conflicts with main · checks failing · layer 2 of 3 of stack #480`) and the failed checks. They stay in place and readable while the row is hovered: its buttons sit before them (`design/sidebar.md`).
- **The stack** (#448 upstream): `#480 on main · layer 2 of 3`, then the layers top first, each with its position, number, sign, title and the workspace of this project that holds it (the one whose pull request has the layer's address, this workspace first); merged ones purple, closed ones crossed out, this one tinted. A click on another layer that a workspace holds goes there and closes the dialog. This layer's sign comes from its own checks, so it never contradicts its row (a layer's `checks` is GitHub's own rollup state). Layers come bottom first without their positions, so they count from this one's (`Stack::rungs`), and the list agrees with the row even if a layer were missing. A line says what blocks the merge (`Stack::blocker`, the TUI's rule: the lowest open or draft layer below that conflicts or failed its checks, else the lowest with changes requested; merged and closed layers never block), in red, orange or grey; a merged layer below while the branch is behind its remote asks to pull before pushing again. Working these out from the layers is drawing what the session gives, not redoing the server: `status` lists the layers for clients to draw.
- **GitLab** (#402 upstream): `provider` `gitlab` gives the dialog GitLab's words (`Merge request !486`, `pipeline`, `Open on GitLab`), while the row keeps `#486`, as the TUI's. An older server sends no provider, read as GitHub.
- **No pull request**: ⌘P toasts `No pull request for <branch>`, or that the workspace is not on a branch. Why gh found none (not installed, logged out) shows where the TUI shows it: in the note of Settings › Worktrees › pull requests, which `config --json` carries.
- **Ask agent** is `Store::ask_agent`, shared with the Changes panel's hunks (`design/changes-panel.md`): it pastes into the workspace's agent (the shown tab's first) with `send` and no Enter, so a note can follow, focuses it and toasts; without an agent it copies the text.
- Checked live on 2026-11-01 with cornercase 0.12.234, on a throwaway project of three plain workspaces with fake pull requests injected into `view` by a `CORNERCASE_BIN` wrapper (a stack of three: a merged one, one conflicting with failed checks and behind its remote, one pending): ⌘P opening and closing it, the tags and their colours, a click on another layer (it went to that workspace), a click on a row's tag, Escape. Not pressed: Copy link and Ask agent (no agent there, so it copies), which would replace the clipboard, and Open on GitHub (fake addresses). GitLab's words are covered by tests only.
