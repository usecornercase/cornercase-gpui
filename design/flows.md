# Flows

Code: `src/panels/flows.rs`, `src/panels/flows/`

The Flows sheet shows teams of agents run by an orchestrator (`cornercase flow`): the flows (built in, yours and the project's) and their runs, live. The Flow panel, docked beside the terminal, shows the run of the workspace the window shows. A run shows its team, its plan lit up where the work stands, the messages the team sent each other and the files of its folder; a flow shows its plan, its roles and the actions `cornercase flow` offers.

## Reading

- **Runs follow `flow runs --follow`**; when the stream ends (the server restarted or went away) the panel says why and follows again after the poll interval, rather than leaving the list frozen.
- **Only the selected run's messages are followed** (`flow messages --workspace … --follow --json`), and only while the run is live: a closed run keeps no feed, and the page says to reopen the agents to follow it again. Switching to another run clears which messages were expanded; the same run keeps its messages across a resync.
- **A `dropped` frame means the command fell behind**: the stream is restarted, which replays what the server keeps. Messages are appended only when newer (`seq` counts from 1 per run), so the replay does not duplicate them. The panel keeps the last 256, as the server does.
- **The list and the selected run's files are read again every 3 s while the sheet shows** (`flow list --json`, `flow files --json`); there is no stream for either. The list is read with the shown project, so a project's own flows appear too, and a read in flight is not started twice.
- **After a start, the new run is selected once `flow runs` lists it**: the panel retries every 500 ms for 10 s, since `flow run` answers before the runs stream reports it.
- **Selection falls back** to the first run, else the default flow, else the first flow, whenever what was selected disappears.

## A run's files

- **In the Flow panel a file opens in the Files panel, and its back button goes back** (0.12.240): the viewer's back button says `‹ Flow`, and the Flow panel comes back as it was left, since it is alive behind the dock and its list keeps its place. The request goes through the Store (`Store::read_run_file`), as a panel cannot reach `Root`, and the Files panel takes it even when this builds it. Until 2026-11-06 a click opened the default app there, which left the agents' answers one window away; on another machine it only copied the path, and `files read` takes an absolute path on the server's machine, so now it reads there too. **Open folder** stays with the file manager.
- **Where it came from is forgotten** when the Files panel closes or another file opens in it (`‹ Files` then, the tree behind it), and once the run is gone the button says `‹ Files` and shows the tree.
- **The Flows sheet keeps the default app**: it may show a run of another workspace, and a sheet that closes itself to open a file in the dock would lose the page the user was on.
- Checked live on 2026-11-06 (debug build, cornercase 0.13.1, Linux x86_64 under Xvfb with lavapipe, a private server whose agents are a fake script; no macOS, no Windows): the Quick flow, the panel scrolled to its files, a file opened, `‹ Flow` back at the same scroll; closing the panel, then `‹ Files`; the run ended with its file open, then the tree. Over ssh it was not tried.

## The model

- **A flow's key is origin, name and path**: a project's flow may share a name with yours, so the name alone does not tell listed flows apart.
- **Names compare trimmed and ignoring case**, as cornercase's `store::same_name` does. Duplicating `Quick` gives `Quick 2`, then 3 and on, counting built-in names (reserved even while hidden) and deleted built-ins.
- **Ordering sends each name once**: `flow order` refuses a name twice, and yours and a project's flow of the same name share one place in the order.
- **Stages**: the contract's `back.to` counts stages from 1; run positions and edges (`stage`, `Edge`) count from 0. The orchestrator has no colour slot; roles take the group presets without red (failed) and orange (waiting), in their order.
- **Tags show only the uncommon cases** (default, this project, yours, edited), as the TUI's lists do.
- **A run is `closed`** when its agents are closed (it can be reopened or forgotten) and **ended** once the orchestrator marked its pane for review. "Stop" closes the orchestrator, else any member still open: closing either closes the whole team.
- **Message text is cut at 32 KiB by the server**; `bytes` is the real size, and the page says so when a message shown whole was cut. Collapsed messages show 1,200 characters, four lines.
- **Times are parsed locally** (`epoch`, Howard Hinnant's days-from-civil algorithm, shared with the Usage panel) since cornercase writes UTC stamps and the app takes no date crate for this.

## The diagram

- **The TUI's shape, drawn as a graph** (redrawn on 2026-10-26, when the boxes stacked with `↓` glyphs were asked to look striking): the orchestrator on top, apart, over a dashed rule that says it moves the work; stages top to bottom on a numbered rail, parallel roles side by side on one centred column; the end at the bottom, a pill with a diamond on the rail. Every role of a stage is wired to every role of the next, and the curves meet at a box's top so a fan-in reads as a merge; a junction dot between stages was the other idea, with fewer wires but one more shape to read.
- **Laid out in plain numbers, painted with gpui's paths**: `graph.rs` places every box, marker, wire and label without a window, so the shape is tested; the boxes are divs placed at those numbers, and the wires are cubic Béziers on a `canvas` (`wires.rs`), each a gradient from its source role's colour to its target's, since gpui 0.2.2 fills a path with a `linear_gradient` over the path's bounds. Divs alone draw only straight, square lines.
- **Loops are brackets on the right**: out of a stage's rightmost box, up a lane right of every box they span, back into the target's rightmost box. Overlapping loops take lanes further out, shortest first; where loops leave and reach one box, their ends spread over its edge (leaving on top, the outer arrival higher), so no two lines cross or share an end. A loop's label sits on its first stretch when that is long enough and no other loop crosses it, else in a column right of every lane, beside its stage. A step outside the plan is the same bracket on the left, dashed, in the waiting colour.
- **It fits the board's width rather than scrolling sideways**: in a container that scrolls only horizontally, gpui 0.2.2 turns the wheel's vertical delta into horizontal scrolling, so scrolling the page over the diagram slid the diagram instead (seen live). The board measures its width in a canvas's prepaint and asks for one more frame when it changes; `graph::fit` first uses the loops' short labels (`findings ≤ 3`, as the TUI falls back to a short form) and only then narrows the boxes, by bisection, to a floor below which it clips. Label widths are estimated from their length, since the layout runs without the text system; too wide an estimate only leaves space.
- **A run lights it up as the TUI does**: the rail fills with cobalt up to the active stage; a working role's box takes its colour as border and glow, the holder's a stronger tint, a closed member's fades; the wire the work last took is drawn whole with a halo, from the colour of the role it left to the colour of the one it reached, only on the branch into the role that got the work when the role it left is in that stage; wires already travelled stay half lit and those ahead faint; a loop past its limit and a step outside the plan turn orange; the end turns cobalt once reached. A click on a box goes to its pane in a run, and in a plan opens its role's prompt under Roles, with a ring on the box.
- **Motion**: on selection the orchestrator, each stage and the end rise and fade in one after another, keyed by the flow or the run, so a run's updates do not replay it; switching to another flow or run and back does. A spark travels the last step for a second, as the TUI's `●` does, keyed by that step, so a new step plays once. Nothing repeats: gpui drops the state of what it did not draw, so an animation would start over each time a run's plan scrolled back into view (its page is a list, next section) and each time the sheet opened; `diagram::Played` notes when each one began, for the selection shown, and once it is over the plan is drawn still.

## The look

- **A role's head has its name and chips on one row** (wrapping), with a slot under them for one more line (`flow_page::role_head`), shared by the flow page's Roles and the editor's closed rows, whose slot holds the prompt's first line.
- **Each flow has a glyph**, its plan in miniature: a dot per role in the role's colour, a row per stage; a run's glyph dims the stages behind and ahead of the active one. It marks the flow in the list, the start dialog and the header, so flows tell apart at a glance; a run's glyph carries its loudest member status as a dot, as the TUI's badge does.
- **A row's name comes first, with its tags and the agent count after it** (the runs, the flows and the start dialog): the name sits in a flex box, since as a block box beside the tags it was laid out at no width and no row showed its flow's name (reported on 2026-11-01; the trap is under "A text kept to one line" in `design/widgets.md`); the file path under a flow's header was blank for the same reason. Short of room, the name is cut first and the tags and the count stay, as the TUI's start dialog cuts the name to fit its tags and count: at the list's narrowest (240 px) a flow that is both the default and the project's keeps none of its name. Checked live on 2026-11-01 (debug build, cornercase 0.12.234, fake runs and flows through a `CORNERCASE_BIN` wrapper) at 1280×800 and 900×700, the list at 330 and 240 px.
- **The header** is a card washed with cobalt and the team's first and last colours, with the glyph, the name, the facts and tags, the team as a stack of faces (initials on the role's colour; the orchestrator a cobalt disc with the `waypoints` icon, as on its box), what stops it from starting, and the actions: Start, the edit and Duplicate with labels, the rest as icon buttons with tooltips. A run's header has its state as a pill and a bar of its stages. Its facts wrap, one after another, each with the dot before it, so a dot never ends a line apart from its fact; a fact wider than the header (a run's place with a long branch) takes a line of its own and ends in "…" (`ui::one_line` in a flex box): as plain text it could neither break nor shrink, so it ran past the card and under the pill (reported on 2026-11-01).
- **A run's page** reads top down: the task as a quote, the team as a grid of cards (a status dot on each face, the branch, the awaited work, the pane), the plan, the messages as a timeline whose dots take the colour of the role each went to, and the run's files.
- **A run's page is a gpui `list`, so only what shows is laid out** (asked for on 2026-10-30: the sheet scrolled slowly). gpui 0.2.2 lays out all a scrolled div holds on every frame, and a run keeps up to 256 messages: with 256 a frame took about 34 ms (30 frames a second), and every frame paid it, also the ones the working orbits draw (`design/widgets.md`). Its parts (`run_list.rs`) are the top (header, task, team and plan, one item), the messages' heading, each message, "Not following" and the files, drawn through `cx.processor`, so they keep the panel's listeners; now a frame costs under 2 ms of drawing and the sheet keeps the display's rate (measured on 2026-10-30, release build, 1280×800, a fake run of 256 messages through a `CORNERCASE_BIN` wrapper). The parts are keyed (a message by its `seq`): a new message is spliced in at the top of the feed and the oldest out past 256, so the view stays on the message it showed; another run starts at its top. A flow's page stays a scrolled div: one diagram and a few cards cost about 2 ms a frame.

## The Flow panel

- **A docked panel shows the shown workspace's run** (`dock.rs`), as the TUI's Flow panel (`Side::Flow`, #263 upstream): the Flows sheet's run page (header, task, team, plan, messages, files) beside the agents at work, so the plan lights up while they work, which the sheet covered. It is a second `FlowsPanel` in its dock place (`Place::Dock`), not a panel of its own: the run page is drawn by the sheet's methods, and only the selection, what is read and the outer layout differ. It follows `flow runs` and the run's messages itself, selects the run whose workspace the window shows (`dock::shown_run`) whenever the store or the runs change, reads no flow list, and reads the run's files every 3 s while it shows. When `flow runs` stops, it keeps the run it showed and says why above it until it follows again, as the sheet says so above its runs; a run kept without that line would look live while nothing updates it. Its team takes two columns from 480 px of width, else one (`run_page::team_columns`, the sheet's too), from the board's measured width.
- **A width of its own, half the window up to 720 px until dragged**, as the Browser's (`DockWidths::wide`): at the 428 px the other docked panels share, the diagram's board has about 340 px, and its narrowest shape (132 px boxes, the loops' short labels in their column) needs 418 px for Quick and 536 for Full issue, so the boxes and the labels were cut on both sides (seen live on 2026-11-01). Stacking a stage's roles under a bracket, as the TUI's panel does below 14 columns a box, was the other way: it fits any width but needs a second layout of the boxes, wires, loops and labels. Half of a 1280 px window fits every built-in flow; dragged narrower, the diagram clips as the sheet's does below its floor. Changing between it and another docked panel resizes the terminal, as the Browser does.
- **Shown only while the shown workspace runs a flow**, as in the TUI: `PanelKind::shows` reads it from the session (a pane with a `role`, which cornercase sets on every member of a live run, the orchestrator included), so `Store::shown_dock` hides it in another workspace, the terminal gets the width back, and going back shows it again. A run whose agents are closed has no member panes, so it hides too, as the TUI's does; the Flows sheet still reopens or forgets it. The session rather than `flow runs` decides, so `Root` knows while it lays out; a run `flow runs` has not listed yet reads "Reading the run…" for that moment.
- **Four ways in**, the TUI's: View flow in a run workspace's menu (`show flow` there), which shows that workspace too; ⇧⌘F, which says "This workspace runs no flow" elsewhere, as `w f` does; the rail's Flow slot, under the other docked panels and only while the shown workspace runs a flow; and a start with "Show it in the window" (under Actions). Its icon is `waypoints`, the orchestrator's, apart from the Flows sheet's `workflow`. ⇧⌘F was free and names it, as `f` does in the TUI's chord.
- **A message's header wraps** when it is narrow: its number, age and copy button go under the names and the step's chip, at the right, rather than past the card's edge (seen in the dock at 428 px).
- **Checked live on 2026-11-01** (debug build, gpui 0.2.2, cornercase 0.12.235) on an isolated server with a throwaway project of two workspaces, through a `CORNERCASE_BIN` wrapper that gave one workspace's panes roles in `view`, faked `flow runs`, `flow messages` and `flow files`, and recorded and answered `flow run` (moving the view with `focus` when sent with `--focus`), so no agent started: View flow only in that workspace's menu, showing it with the panel; the panel and its rail slot gone in the other workspace and back on return; ⇧⌘F closing and opening it there, and saying "This workspace runs no flow" elsewhere; a start from the project's menu and one from the Flows sheet, each showing the run's workspace with the panel, the sheet closed; at 428 px the diagram cut on both sides, at 640 px (half the 1280 px window) whole, with the team in two columns. Not checked live: a start without "Show it in the window" (it opens nothing, as before), dragging the panel's width, and a run whose agents close.
- **The tours keep the Flows sheet**: cornercase's Flows chapter shows the Flow panel (`panel: flow`) in its first two steps, what a flow is and how to start one, which the panel cannot show without a run, so here they still open the sheet (`design/tour.md`).

## Actions

- **Edit and New open a form that follows the plan, with the plan beside it** (`editor.rs`, `editor_view.rs`, `editor/`, the model in `draft.rs`; #109), saved with `flow save - --json` (usecornercase/cornercase-terminal#465, closed in 0.12.225): the flow goes as JSON on standard input, a file's flow with `--path` (a new name renames the file), a built-in's into yours (that makes your version of it, as editing one in Settings › Flows does), a new one into yours or, with a project shown, the project's. The form reads in the plan's order: About (name, description, where it saves, notes behind a button), the orchestrator as a row, each stage as a block holding its roles as rows, one open at a time, then its loop as a sentence, and the end. Rejected: tabs (the plan's order is lost), a wizard (an edit is not a sequence), only folding the old form (its stage row of five typed fields stays), dragging on the diagram (no keyboard, no touch). What is rarely set (notes, arguments and variables) waits behind a button; a role's closed row is the flow page's (`flow_page::role_head`, name and chips on one row, now on the page too) with the first line of its prompt. Roles sit inside their stages, which is what cornercase's check allows: every role in exactly one stage, no stage empty (the limit of 8 roles is left to the strip). Stages hold role ids (`draft::Stage`), so a rename needs nothing and stages are never typed again; Works in moves a role to another stage or to a new one (last in it), a stage has no bin and goes with its last role, with the loop toast of `loop_after`'s rules. A role's colour is its place in `roles`, which a move never changes. The orchestrator has no name field (cornercase calls it orchestrator, and the TUI's tab has none) and the form no longer writes its name. The form takes the window while it is open, so a click on the list cannot drop an edit; Cancel with changes asks first, inline.
- **The check is a pill and a strip** (`editor/check.rs`): 400 ms after the last change the draft goes to `flow save --check --json`, and the header's pill says `Checking…` the moment anything changes, then `Ready to save` or `N problems`. The strip under the header lists cornercase's problems in red, the form's own error (a variable with no `=`), a refused save's reason and, in orange, what a project's flow runs unattended and the line of a mismatched file. The strip keeps the last answer's lines while it checks, so the columns do not jump on every key, and it caps its height at 160 px and scrolls. Save rests while there are problems, and Enter and ⌘Enter do nothing then. A check that could not run (the server did not answer) shows its reason in the strip under a muted `Not checked` pill and does not rest Save, which cornercase's own save still guards. The check's list may also hold a name conflict that cornercase's save would not refuse; the JSON gives plain sentences, so the window cannot tell them apart and Save rests on those too (`design/upstream-gaps.md`; a first edit of a built-in raises none, as cornercase's `save_problems` ignores built-ins when there is no `--path`). Agents, models and efforts are text, not picks: no command lists the agents a flow takes with their models and efforts (`config --json`'s `agent` setting lists agents flows refuse; #704 upstream), so the check names the valid ones, and a muted line under the agent, model and effort of the open role and of the open orchestrator names the issue.
- **Loops read as a sentence** (`editor/loops.rs`, from `flows/brief.rs`): `If it reports [when]`, then `go back to stage (1)(2) at most [−] 3 [+] times`, with segments for earlier stages only and a stepper from 1 with no ceiling. Add a loop back adds cornercase's default (1, `problems`, 3). Moving or removing stages keeps today's rules (`loop_after`, `swapped`, `without`) and toast.
- **A mismatched file is seated, not refused** (`draft::seat`): names compare exactly, as cornercase's check does, so a flow it accepts is never touched. A role no stage names gets a stage of its own, a name no role has leaves its stage, a role named twice stays in its first stage, a stage left empty goes with its loops. The form opens with an orange line saying what changed, and Cancel asks first.
- **The draft edits the flow as cornercase wrote it**: `flow list --json`'s `flow` is kept raw (`FlowInfo::raw`) and the form writes only its own keys into it, so a key the form does not show (one a later cornercase adds) is saved unchanged; `flow save` takes left-out keys as defaults, so rebuilding the flow from the typed model would reset them. An empty model or effort is `null` (the agent's default).
- **Prompts and notes hold several lines** (2026-11-06, `TextField::multiline`, `design/widgets.md`), as the TUI's do: three rows to twelve, then the field scrolls, so a long prompt does not push the rest of the form away. Enter breaks the line there, so saving from one of them takes ⌘Enter (Ctrl+Enter on Linux and Windows) or the Save button; Enter in a field of one line still saves. A description stays one line that wraps, because cornercase refuses a line break in it (`control_problems`, "contains a control character"); one that already holds a break, from a file written by hand, opens with several lines, so the break the check complains of can be seen and removed. The read-only text these fields fell back to is gone: nothing in the form needs the file any more. **A stage has no prompt**: cornercase's `Stage` is `roles` and `back`, so there is nothing of the kind to edit.
- **Stages move with ↑ and ↓ beside each one** (2026-11-06), the buttons the flow list's own order uses, dimmed on the first stage's ↑ and the last's ↓. A drag was the other idea; it would show nothing more, since each press already shows the order and the plan, and would need a drop target between rows that hold fields. The buttons stay where they are while the stage moves, so a second press at the same spot moves it back.
- **Loops keep pointing at the same stages** (`loop_after`, `swapped`, `without`), the TUI's rules for `move_stage` and `remove_stage`: moving a stage, or removing the last role of one, renumbers every loop that names it or one after it; a loop whose target is gone, or that would no longer go back to an earlier stage, is dropped, since a flow with such a loop cannot be saved. The TUI drops a loop in silence with its diagram beside the form; here the plan is hidden in the narrow layout and, beside the form, a loop vanishing from a box is easy to miss, so a toast names the stage that lost it.
- **Arguments and variables have a field each** (2026-11-06), words as a shell reads them, as the TUI's `args` and `env` rows: `--flag 'two words'`, `KEY=value 'PLACE=the big house'`. Quoting was kept over one word per line because it is what the TUI shows and people copy from a command line. `split_words` and `quoted` give back what they read, so an untouched flow saves unchanged (`an_untouched_draft_gives_back_the_same_flow`). A variable with no `=` or no name is the form's own error, in the verdict's place: `flow save` takes a map, so there would be nothing to send. What these make a project's flow run unattended still comes back from the check, in orange.
- **The draft's plan is drawn beside the form** (`editor/plan.rs`, `Draft::plan`): the JSON the form would save, read as the `FlowSpec` the flow's page draws, so it is the same diagram, redrawn with every change, for any flow and not only a built-in. From 1,000 px of editor width it is a column on the right: `graph::fit(…, 0.).width` (the narrowest shape) plus the board's padding and border and the column's padding, between 42 % and 58 % of the editor (606 px for Full issue at 1,050; the issue said 604, leaving the board's border out); each column scrolls by itself. **What changed since it was turned down there** (the sheet is at most 1,100 px wide and a plan with three roles side by side needs about 500): the row of four role fields and five stage fields went, so the form needs about 440 px. Below 1,000 px there is one column and `Form | Plan` in the header, as the TUI's ` form ` / ` diagram `. A click on a box opens that role and focuses its name (`Plan::on_role`; on the narrow layout it switches to Form first, or the focused field would not be drawn); a click on the open role's box closes it, and the open role's box has the ring (`Plan::focus`). The editor keeps its own `board` and `Played`, since the panel's are the page's. A draft that cannot be read keeps the last plan, with the reason in the strip.
- **What is still text**: the agent, model and effort of each role (see the check's bullet), where the TUI has picks. The file stays a click away (Open its file, for flows that have one).

- **Share copies the flow's TOML** (`flow export --json`) to paste to a teammate or commit; `flow import -` or Import… adds it.
- **Delete depends on the flow**: a built-in is hidden (it keeps its name, Restore brings it back); your edited built-in is deleted and the built-in hidden; a file is deleted from disk. Everything that cannot be undone (delete, hide over an edit, stop, forget, restoring a built-in over yours) asks first in the panel's own dialog, which runs the command and reads the flows again.
- **Import** takes a file, an https:// address, a GitHub `owner/repo` or the TOML on the clipboard, into yours or the project's, under its name or another, replacing on request. It goes in two steps (usecornercase/cornercase-terminal#466, closed in 0.12.225): Check runs `flow import … --check --json` and shows where the flow goes, its roles with their agents, its risks (variables and arguments, which run without asking) in orange and its missing agents; Import then runs it with `--yes`, since the CLI's own question cannot be answered from a window and the dialog has just shown what it would ask. Any change to the form drops the check, so what is imported is what was checked (`--check` and `--yes` cannot be combined).
- **Start** works as the TUI's start dialog: the project, the flow (the default one when it can start, else the first built-in that can, else the first that can), the task, an issue or both, and an optional branch. The task is `TextField::prompt()`, as the TUI's holds several lines (2026-11-09, #87; `design/widgets.md`): Start or ⌘Enter starts; the issue, branch and workspace name stay one line, and Enter in them starts. Changing the project reads that project's flows, keeping the chosen flow by name; an answer for a project no longer chosen is dropped. The dialog stays open and busy until `flow run` answers, and shows a refusal in red, as a sentence (`cli::reason`), with the task kept. Each value goes joined to its flag (`--prompt=TEXT`, `--workspace-name=NAME`): as two arguments, clap took a task starting with `-` (`- fix the tests`, `--help is wrong`) for an option and refused the start (checked on 2026-11-02 with cornercase 0.12.240).
- **The accounts**: under the branch, as upstream's (its `design/accounts-and-profiles.md`), a dropdown per agent of the selected flow's team that has accounts, side by side, each on the one in use (`design/accounts.md`, An account where agents start). Only those of the selected flow go, one `--account` per pick; a pick stays when another flow is selected. A flow's run resolves its accounts when it starts, so the team keeps them whatever is chosen later. A refusal shows in the dialog with the rest, and a pick clears it.
