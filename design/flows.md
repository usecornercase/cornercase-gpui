# Flows

Code: `src/panels/flows.rs`, `src/panels/flows/`, `src/model/reopen.rs` (`Workspace::reopen`, `Reopen`), `store::reopening` and `Store::reopen_agents` (`src/store/jobs.rs`, `src/store.rs`), the row's `N exited` in `src/sidebar/workspace.rs` and the menu's Reopen in `src/sidebar/menus.rs`

The Flows sheet shows teams of agents run by an orchestrator (`cornercase flow`): the flows (built in, yours and the project's) and their runs, live. The Flow panel, docked beside the terminal, shows the run of the workspace the window shows. A run shows its team, its plan lit up where the work stands, the messages the team sent each other and the files of its folder; a flow shows its plan, its roles and the actions `cornercase flow` offers.

## Reading

- **Runs follow `flow runs --follow`**; when the stream ends (the server restarted or went away) the panel says why and follows again after the poll interval, rather than leaving the list frozen.
- **Only the selected run's messages are followed** (`flow messages --workspace … --follow --json`), and only while the run is live: a closed run keeps no feed, and the page says to reopen the agents to follow it again. Switching to another run clears which messages were expanded; the same run keeps its messages across a resync.
- **A `dropped` frame means the command fell behind**: the stream is restarted, which replays what the server keeps. Messages are appended only when newer (`seq` counts from 1 per run), so the replay does not duplicate them. The panel keeps the last 256, as the server does.
- **The list and the selected run's files are read again every 3 s while the sheet shows** (`flow list --json`, `flow files --json`); there is no stream for either. The list is read with the shown project, so a project's own flows appear too, and a read in flight is not started twice.
- **After a start, the new run is selected once `flow runs` lists it**: the panel retries every 500 ms for 10 s, since `flow run` answers before the runs stream reports it.
- **Selection falls back** to the first run, else the default flow, else the first flow, whenever what was selected disappears.

## A run's files

- **In the Flow panel a file opens in the Files panel, and its back button goes back** (0.12.240): the viewer's back button says `‹ Flow`, and the Flow panel comes back as it was left, since it is alive behind the dock and its list keeps its place. The request goes through the Store (`Store::read_run_file`), as a panel cannot reach `Root`, and the Files panel takes it even when this builds it. Until 2026-11-06 a click opened the default app there, which left the agents' answers one window away; on another machine it only copied the path, and `files read` takes an absolute path on the server's machine, so now it reads there too. **Open folder** stays with the file manager.
- **Where it came from is forgotten** when the Files panel closes or another file opens in it (`‹ Files` then, the tree behind it), and once the run is gone the button says `‹ Files` and shows the tree.
- **The Flows sheet keeps the default app**: it may show a run of another workspace, and a sheet that closes itself to open a file in the dock would lose the page the user was on.
- Checked live on 2026-11-06 (debug build, cornercase 0.13.1, Linux x86_64 under Xvfb with lavapipe, a private server whose agents are a fake script; no macOS, no Windows): the Quick flow, the panel scrolled to its files, a file opened, `‹ Flow` back at the same scroll; closing the panel, then `‹ Files`; the run ended with its file open, then the tree. Over ssh it was not tried.

## The model

- **A flow's key is origin, name and path**: a project's flow may share a name with yours, so the name alone does not tell listed flows apart.
- **Names compare trimmed and ignoring case**, as cornercase's `store::same_name` does. Duplicating `Quick` gives `Quick 2`, then 3 and on, counting built-in names (reserved even while hidden) and deleted built-ins.
- **Ordering sends each name once**: `flow order` refuses a name twice, and yours and a project's flow of the same name share one place in the order.
- **Stages**: the contract's `back.to` counts stages from 1; run positions and edges (`stage`, `Edge`) count from 0. The orchestrator has no colour slot; roles take the group presets without red (failed) and orange (waiting), in their order.
- **Tags show only the uncommon cases** (default, this project, yours, edited), as the TUI's lists do.
- **A run is `closed`** when its agents are closed (it can be reopened or forgotten) and **ended** once the orchestrator marked its pane for review. "Stop" closes the orchestrator, else any member whose agent runs (neither closed nor exited, `Run::stop_pane`): closing either closes the whole team. cornercase refuses `close --agent` on a pane that runs no agent, so Stop through an exited orchestrator failed before `exited` was read.
- **Message text is cut at 32 KiB by the server**; `bytes` is the real size, and the page says so when a message shown whole was cut. Collapsed messages show 1,200 characters, four lines.
- **Four fields of a run the window reads** (#207, #215, #258; 2026-11-13): `exited` (a role's agent exited, below; 0.13.71) and `not_run` (the stages, counted from 0, the work has not been through since it last went back; cornercase 0.13.59; left out when empty, kept on a closed run), `stopped` (the UTC time the run stopped moving, set by the server only while the run is live; 0.13.62) and `free_builds` (the run frees its build folders when it closes at the merge; 0.13.64; left out when off). Stages are read from 1, as upstream's `stages_in_words` writes them (`stage 3`, `stage 3 and 4`, `stage 2, 3 and 4`).
  - **An older server leaves them out and the window shows nothing new**, with no gate: for `not_run` absence means none; for `stopped`, telling "moves" from "this server cannot say" needs `contract --json` (already rejected for the close's gate, below) or a 0.13.62 gate, and either would put a line on every run of an older server that says nothing about this run.
- **`stopped` is a time, so the window counts its age** (`Run::standing`, in `model.rs`, one of the files the cached panel's clock list in `tests/layers.rs` allows; `run_page.rs` and `list.rs` reach the clock only through it, which that lexical check cannot see, so the dock's 1-second tick and the sheet's 3-second poll are what keep their ages fresh; the list only shrinks, so no file was added to it) and shows a stop **once it is 60 seconds old** (`STOPPED_AFTER`): the server sets it in the step where a member finishes, before it wakes the orchestrator, so a stop of a second or two is a hand-over and not a stop (inferred from upstream's `follow_sent_work`; on the bench a run reads `stopped` from the first moment its idle agents have started, and a real stop lasts minutes). Showing it at once, or at 30 s, was rejected: it would flash at every hand-over.
- **Times are parsed locally** (`epoch`, Howard Hinnant's days-from-civil algorithm, shared with the Usage panel) since cornercase writes UTC stamps and the app takes no date crate for this.

## The diagram

- **The TUI's shape, drawn as a graph** (redrawn on 2026-10-26, when the boxes stacked with `↓` glyphs were asked to look striking): the orchestrator on top, apart, over a dashed rule that says it moves the work; stages top to bottom on a numbered rail, parallel roles side by side on one centred column; the end at the bottom, a pill with a diamond on the rail. Every role of a stage is wired to every role of the next, and the curves meet at a box's top so a fan-in reads as a merge; a junction dot between stages was the other idea, with fewer wires but one more shape to read.
- **Laid out in plain numbers, painted with gpui's paths**: `graph.rs` places every box, marker, wire and label without a window, so the shape is tested; the boxes are divs placed at those numbers, and the wires are cubic Béziers on a `canvas` (`wires.rs`), each a gradient from its source role's colour to its target's, since gpui 0.2.2 fills a path with a `linear_gradient` over the path's bounds. Divs alone draw only straight, square lines.
- **Loops are brackets on the right**: out of a stage's rightmost box, up a lane right of every box they span, back into the target's rightmost box. Overlapping loops take lanes further out, shortest first; where loops leave and reach one box, their ends spread over its edge (leaving on top, the outer arrival higher), so no two lines cross or share an end. A loop's label sits on its first stretch when that is long enough and no other loop crosses it, else in a column right of every lane, beside its stage. A step outside the plan is the same bracket on the left, dashed, in the waiting colour.
- **It fits the board's width, and scrolls sideways only below what it can shrink to** (#170, 2026-11-13). `graph::fit` first uses the loops' short labels (`findings ≤ 3`, as the TUI falls back to a short form) and then narrows the boxes, by bisection, to `MIN_CARD`; label widths are estimated from their length, since the layout runs without the text system. A plan still wider than its board scrolls sideways inside it (`diagram::plan_block`, in all four places the plan is drawn: a flow's page and a run's page, the docked panel and the editor), instead of being clipped. It never scrolled before because, in a container that scrolls only horizontally, gpui 0.2.2 turns the wheel's vertical delta into horizontal scrolling and scrolling the page over the diagram slid the diagram. `restrict_scroll_to_axis` (`widgets::own_axis`) answers that on the plan's scroller and on the page's and the editor's plan column (gpui maps a lone `delta.x` onto y on a y-only scroller otherwise): the wheel keeps scrolling the page, a trackpad's sideways swipe or Shift and the wheel moves the plan, and `‹ ›` beside the Plan heading step it by 80 % of what shows, only while part of the plan is out of view and resting (dimmed, no press) at its ends (`diagram::sideways`, `can_step`, `stepped`; one pixel of tolerance, so the editor's two-column plan, sized to fit, never shows them). Each flow or run starts at the plan's left edge (`Board::follow`). The arrows notify the view, not the window, since the docked panel is a cached view. The board measures its width in a canvas's prepaint and asks for one more frame when it changes. The scroller takes the board's side padding as its own, so the plan keeps 18 px of air at both ends of its scroll and is cut at the board's border while it scrolls. The tab strip (`design/terminal.md`, "Tabs past the edge scroll") is the precedent for `‹ ›` arrows that appear when content overflows; its helpers live in the window layer (`tabs/strip.rs`, which only the window files may reach), so the plan has its own small ones, with a plan's step of 80 % of what shows where the strip steps by tab. Rejected: a scrollbar (gpui 0.2.2 draws none for a div), arrows on the board's sides (they cover its edge).
- **A run lights it up as the TUI does**: the rail fills with cobalt up to the active stage; a working role's box takes its colour as border and glow, the holder's a stronger tint, a closed member's fades, an exited member's edge is dashed in the waiting colour; the wire the work last took is drawn whole with a halo, from the colour of the role it left to the colour of the one it reached, only on the branch into the role that got the work when the role it left is in that stage; wires already travelled stay half lit and those ahead faint; a loop past its limit and a step outside the plan turn orange; the end turns cobalt once reached. A click on a box goes to its pane in a run, and in a plan opens its role's prompt under Roles, with a ring on the box.
- **Motion**: on selection the orchestrator, each stage and the end rise and fade in one after another, keyed by the flow or the run, so a run's updates do not replay it; switching to another flow or run and back does. A spark travels the last step for a second, as the TUI's `●` does, keyed by that step, so a new step plays once. Nothing repeats: gpui drops the state of what it did not draw, so an animation would start over each time a run's plan scrolled back into view (its page is a list, next section) and each time the sheet opened; `diagram::Played` notes when each one began, for the selection shown, and once it is over the plan is drawn still.

- **Stages not run are rung in the waiting colour** (#207): a stage that `not_run` names has its marker drawn with the ground fill, a ring and a number in the colour of the plan's other off-plan signals (the outside bracket, a loop past its limit); the active stage keeps its own look, since the server takes a stage off `not_run` at the send that makes it active. Only run pages: a flow's page and the editor have no run. Rejected: a note under the board beside `outside the plan`, which would say again, one block lower, what the run's header says in words; the markers show where the owed stages sit in the plan, which a sentence cannot. `stopped` draws nothing on the plan: it is about the team.

## The Flow panel

- **A docked panel shows the shown workspace's run** (`dock.rs`), as the TUI's Flow panel (`Side::Flow`, #263 upstream): the Flows sheet's run page (header, task, team, plan, messages, files) beside the agents at work, so the plan lights up while they work, which the sheet covered. It is a second `FlowsPanel` in its dock place (`Place::Dock`), not a panel of its own: the run page is drawn by the sheet's methods, and only the selection, what is read and the outer layout differ. ## A role whose agent exited

Decided for #258 (2026-11-14), checked live as the last entry says.

- **What it is.** From cornercase 0.13.71 (upstream #826, feature `flow-exited`) `flow runs --json` gives a role `exited: true` when its agent exited by itself (a crash, a signal, `/exit`) and its tab is still open, and a workspace's `run.exited` in `status` and `view` names those roles. It is neither `closed` nor idle: the pane is there, now at its shell, with no agent status. A role `closed` is never exited (`Member::agent_exited`); an ended run still names its exited roles; a closed run names none. Absent and false read as "not exited" (upstream never sends `null`).
- **Its word and look.** `exited` in the waiting colour (orange), the colour Flows already uses for what is off the plan and needs a look: the run cannot go on through that role until a person brings it back. The team card and the plan's box get a dashed edge in that colour, the box with the plain sheen, no glow and no fade; no dot on the face (the dot is the agent's status, and there is none). Exited wins over holder (the work is stuck there) and closed wins over exited. Rejected: red (the agent's own `failed`, and an exit is not always a failure), a grey (idle and closed use them, which is the bug upstream's #829 describes in its own Flow panel), faded (that says "out of the run"), a dot (reads as `waiting`), a status `exited` faked in the model (it would flow into `loudest()` and every badge) and the pill (it keeps the run's standing).
- **Where it is said.** A third note under the stages bar, after the stop and the owed stages (`the agent of coder exited`, `the agents of coder and reviewer exited`), the same line in the runs list, and the sidebar's workspace row, in orange, beside `N closed`: `N exited`. cornercase's own window shows a ▶ there; here the row already says `closed` in words.
- **Where Reopen agents shows, and why: one rule.** `Workspace::reopen` and `Workspace::reopen_for_run` (`model/reopen.rs`, both reading the session's `closed_agents` and `run.exited`) say what one press of `agents reopen --workspace` brings back: the kept (closed) agents first, else the run's exited roles, else nothing, the order upstream's `reopen_workspace` has. The run's page (the sheet and the dock draw the same page), beside Show orchestrator and Stop, and the workspace's menu ask it; no other file compares `closed_agents` with exited roles. A live run's page offers a Reopen only when the run has exited roles of its own: a workspace's other closed agents are not the run's, and the menu offers them. A closed run's page offers it as before. Not on the no-tab page (it shows only for a workspace with no tab, so no live run, and its count writes its own sentence) and not on a toast (nothing tells an exit).
- **Two reopens.** A workspace that kept agents with `agents close` and then ran a flow on that branch has closed agents and exited roles: seen on 0.13.72, the first `agents reopen` brings back the kept tab and leaves `run.exited`, the second brings the role back in its own pane. So every control names what its press brings back (`Reopen 2 closed agents`, then `Reopen 1 exited agent`), the run's note says `; Reopen brings back this workspace's 2 closed agents first`, and between the two the row, the menu and the note change as the session does. Rejected: one label `Reopen agents` for both (one press would bring back only some, and cornercase's TUI counts both together), a resting second button (it would rest with no reason), and chaining the second command after the first (it would reimplement cornercase's order, and a refusal in between would leave it half done).
- **One job per workspace.** Reopen used two keys before (the run page's `flow:` key and the menu's `reopen:W`), so both could run at once. `store::reopening` (key `reopen:W`) is the one job; `Store::reopen_agents` starts it through `Store::run_aside_once`, which drops a start while that key runs, and the page, the menu, the no-tab page and the toast all use it. A success says nothing (what comes back on screen tells it); an error is a toast. The page's old `Reopened the team` toast went with its separate job.
- **Nothing is guessed, no gate.** Only `exited: true` or a name in `run.exited` counts. A server below 0.13.71 sends neither, so the window shows what it showed and offers nothing; a role that has not started has no status either and is not called exited. A field only a new server sends needs no release gate to be read, and the server that says a role exited is the one whose `agents reopen` brings it back. Rejected: `contract --json` and a `…_SINCE` constant.
- **A machine's run** is unchanged: the window opens no run page for it, a machine's workspace row reads no `exited` and offers no Reopen (it offers none for closed agents either).
- **No telling.** cornercase publishes no event for an exit (upstream's own note says nothing tells a person when a role exits), so the window tells none. Rejected: diffing `flow runs` snapshots (a guess that would fire again after every restart or reconnect). Filed upstream as usecornercase/cornercase-terminal#839.
- **Checked live** on 2026-11-14, macOS on Apple silicon, a debug build of this change, cornercase 0.13.72, 0.13.71 and 0.13.70 (release archives, checksums read) on private servers with fake agents; the user's server untouched. From a shell on 0.13.72: ending one role's fake by its pid made `flow runs` print `exited` and `--json` give `exited: true` with `status` null, `status --json` and the `view` stream gave the workspace's `run.exited`, `agents reopen --workspace` answered `tabs: []` with that role's pane and the role came back in it; with a kept agent besides, the first `agents reopen` brought back the kept tab and left `run.exited`, the second brought the role back; 0.13.71 printed the same `exited` in `flow runs`, `--json` and `status --json`, and 0.13.70 printed no key anywhere (the role shows `-`) and answered `workspace N has no closed agents`. In the window with no press: the run's page on 0.13.72 in both themes and at 640 wide (orange `exited`, dashed card, the note, `Reopen 1 exited agent` beside Show orchestrator and Stop, the runs list's line, the sidebar's `1 exited`), the same run on 0.13.70 (no word, no note, no Reopen), and a closed run's page with `Reopen 5 closed agents` and Forget. A second pass on 0.13.72: a workspace with a kept agent and a run whose orchestrator's and coder's agents were ended showed `stopped moving 1m ago: the orchestrator's agent exited` (as `flow runs` says), the third note with `; Reopen brings back this workspace's closed agent first`, `Reopen 1 closed agent` beside Stop, both cards and the plan's box dashed; after the first `agents reopen` from a shell the note lost its tail and the button read `Reopen 2 exited agents`. **Not checked:** any press (a screen-capture window held the screen, so Reopen on the page, in the menu, a second press while it runs and opening a run from the list rest on the unit tests and the shell commands), the docked Flow panel, 0.13.71's `agents reopen`, Windows and Linux.
- **Known upstream.** cornercase's own Flow panel draws such a role as idle (#829) and a `send` into one types into its shell (#830). The window's hand-offs pick panes that run an agent, so none goes there.

## Closing a run once its pull request merges

- **Per run, opt-in, as upstream decided** (#126; cornercase 0.13.33, upstream #734 and #743):
  - The start dialog's box, off by default, sends `--close-when-merged`.
  - The run's page, the same builder in the sheet and the Flow panel (`merged_view.rs`, its rules in `merged.rs`), sets it with `flow close-when-merged --workspace ID [--off | --free-builds] --json` as a job, one job per box, keyed by the workspace rather than the command so the spinner shows whichever way it was pressed, and run without `run_cmd`, since its answer goes into the run and success needs no toast. Its busy row shows only after the job has run `SHOW_AFTER`, with the job's words, as the pane's account switch does: the command answers in a few milliseconds and a spinner would only flash (`design/connection.md`). It takes the answer's `close_when_merged` and `free_builds` into the run at once, so the box does not flick back until `flow runs --follow` sends the change.
  - Rejected:
    - On by default, or remembered: upstream made it per run so that a run started to be watched does not close.
    - A row menu in the runs list: rows have no menu, and the page is one click away.
    - A countdown: there is no `closes_at`, which upstream left for later.
- **A second box frees the build folders** (#215; cornercase 0.13.64 `--free-builds`), nested under the first in the start dialog and on the run's page: `Free the build folders too`, with the line `FREE_HOW` (what goes: the git-ignored build folders of the run's worktree and of its roles' own, once the agents closed; what stays: the worktrees, their branches and the run's folder; reopening rebuilds; a worktree where a program still runs keeps its builds; turning the close off turns this off).
  - **States**: hidden where the first box is hidden or rests (a closed run, a flow that leaves the commits, below 0.13.33); resting with `Needs cornercase 0.13.64 or newer: the server runs X.` below 0.13.64, here or on the machine chosen in Run on; resting, unticked, with `FREE_HOW` while the close is off; otherwise offered. The first box's line loses `Nothing is removed:` while the second is on.
  - **Gate**: `cli::Feature::FlowFreeBuilds` (0.13.64) beside `FlowCloseWhenMerged`; the flag is never sent below it, without `--close-when-merged` (clap refuses) or with `--off` (clap refuses). A machine's run needs both releases and its answer is read for `free_builds: true`; the start's toast says in red that the build folders stay when it is not there.
  - **The page sends the whole choice**: `flow close-when-merged` without `--free-builds` keeps the builds, so a page that sent only the close dropped the second choice of a run started from a terminal with both, silently. Now: off+off sends `--off`, on+off sends nothing more, on+on sends `--free-builds`. No press changes the other box unasked, except that the close off turns the free off (cornercase's rule, said in the line, and the dialog's first box unticks the second the same way); the close turned on again keeps the run's `free_builds`, so after off then on the second box reads off, as the server has it. The window does not remember a choice cornercase dropped. Two jobs, `flow:close-when-merged:ID` and `flow:free-builds:ID`, so the busy row sits where the press was; a press while either runs is dropped, since the jobs run beside the queue and two commands could land in either order.
  - Rejected: no second box (the choice would be terminal-only, and dropped by a press); one box that does both (cornercase keeps them apart, one flag, one meaning); remembering the free across an off/on of the close.
  - **What a closed run says: nothing more than before.** `flow runs --json` cannot tell kept from freed: the automatic close clears both flags on the kept run, a manual close keeps both, and upstream did not add a reason field. Guessing from the flags was rejected.
- **A flow that leaves the commits** rests the box in the dialog, with cornercase's own reason, and has no box on its page: cornercase refuses both. A closed run has no box: cornercase refuses a change until it is reopened. Its automatic close turns the choice off, so a reopened run shows it off. The line under the box names Reopen agents, not cornercase's own window's ▶, which this window does not draw. For a machine's run, whose page and workspace menu this window never opens or offers a reopen in, the dialog's line says that cornercase on that machine can reopen them.
- **Gated by the server's release** (`cli::Feature::FlowCloseWhenMerged`, 0.13.33, `design/connection.md`), as an agent's `default` mode is. The release is `view`'s `version` and, for a machine, `machines --json`'s `server_version`.
  - The flag is never sent below it, and the box rests with a line that names the release.
  - Rejected:
    - Reading `contract --json`: one more read per dialog and per page for what the release already tells. For a machine, the contract asked would be this server's, which only relays.
    - Mapping clap's refusal of an unknown flag, as `TOO_OLD` does: that is text matching, and the gate already keeps the flag from going.
  - A local `cornercase` older than its server still refuses the flag in clap's words, shown in the dialog as they come.
  - The window's minimum stays 0.13.19.
- **A machine's run** needs both releases: this server checks the feature and relays it, and the machine's server does the close.
  - The answer is read for `close_when_merged: true`, as upstream's help says to. Before the machine's first snapshot the relay sends no `boot`, so an older cornercase there drops the field.
  - The start's toast says it closes once merged or, in red, that the agents stay open.
  - No box for a machine's run: its page is never opened (see On a machine).
- **A failed free is told as a failure** (#260, 0.13.72): the toast is orange, see `design/notifications.md`.
- **Once it closes** the window shows what it shows for any closed agents: the run `closed` in the sheet, with Reopen agents and Forget, the Flow panel hiding, the sidebar's `N closed` and the no-tab page's sentence. Upstream's toast is its own window's, and since cornercase 0.13.39 `events --notices` carries it as a `message` event of kind `flow-merged` (from 0.13.64 with how much was freed or why a worktree kept its builds); this window now tells it (#217, `design/notifications.md`, Messages), whole, as a toast with Reopen agents, and a closed run's page still says nothing more. Rejected: guessing the reason from the choice turning off as the run closes, which follows upstream's internals rather than a field.
- **Faking a merge** (#126), for a check: a fake `gh` answering `gh pr view --json number,title,url,state,isDraft,mergeable,baseRefName,headRefOid,statusCheckRollup` with `state` read from a file, `OPEN` and then `MERGED`; the server is pointed at it with the `gh` key of its `config.json`, with `glab` set to `/nonexistent/glab`, and reloads the file by itself; the project's `origin` is on `https://example.invalid/…`. - **Moving a run with fake agents** (#207): `send` and `mark` run from an orchestrator's pane take the caller from `CORNERCASE_PANE` and `CORNERCASE_SERVER` there, so only a send from that pane moves a run. ## The docked panel is drawn cached

- **The docked panel is a cached view** (#134; the rule, the measure and the method are in `design/widgets.md`). It reads its own fields, notified by the `flow runs`, `flow messages` and `flow files` callbacks (the audit added notifies to `sync_feed`, which clears or restarts the feed, and to an unreadable `flow runs` line), `Store` (`DockKey`), and the diagram's one-shot rise and spark, the width feedback of `wires.rs` and, since #170, the plan's sideways scroll: its `ScrollHandle` is the panel's own state read at render, and its `‹ ›` arrows notify the panel (`cx.notify(view)`), as gpui's own scroll listener does.
- **The ages count every second while the docked panel shows a run**: "5s" and "3m" read the wall clock at render, so a one-second task (`count_ages`, `ages_tick`) notifies the panel then. A visible change: before, the ages stood still when no agent was working, since nothing redrew the window. The Flows sheet is not docked, so it is not cached and has no tick. A stopped run's age and pill move on the same tick (the pill turns at the tick that reaches a minute); the sheet's move when it redraws, which its 3-second poll guarantees while it shows, so they are at most about 3 seconds late, in words of minutes.
