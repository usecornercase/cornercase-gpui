# Session model

Code: `src/model.rs` (the session, `cornercase view`), `src/model/surface.rs` (frames, `cornercase surface --patches`), `src/model/grid.rs` (the grid frames and patches build up)

- **Local serde types mirror cornercase's JSON**, every struct `#[serde(default)]`: a field cornercase adds or drops does not break parsing, and the client reads only what it draws. `Style`, `Modes` and `PaneInfo` keep cornercase's flags as plain `bool`s (with `#[expect(clippy::struct_excessive_bools)]`) rather than enums of our own, so they stay one-to-one with the wire format. `Style::underline_kind` reads the wire field `underline_style`; it is renamed only because clippy rejects a field named after its struct.
- **`name` and `custom_name`**: `custom_name` is the name given in cornercase, if any; `name` already falls back to the folder's. Rename fields start from `custom_name`.
- **`config.revision`** grows with every change to the settings (`cornercase config`); the Settings panel compares it (with `boot`) to notice settings changed elsewhere, in the TUI or by an edit of `config.json`, without following a stream of its own.
- **Workspace extras**: `pull_request` carries its checks rollup (`failing`, `pending`, `passing`, or none without checks) and `state` (`open`, `draft`, `merged`, `closed`); `setup` is the project's setup in that workspace (`running` or `failed`); `changes` counts what changed as the Changes panel does; `closed_agents` counts agents closed with `agents close`, waiting for `agents reopen`.
- **Pane extras**: `parent` is the agent that started this one (the agents tree); `subagents` counts the subagents an agent runs inside itself (Claude Code's tasks); `role` is its role in a flow run; `collapsed` folds away the agents it started.
- **Loudest status**: a tab, workspace or project shows the status of its pane that most asks for attention, ranked `waiting` > `failed` > `done` > `pending` > `working` (`status_rank`, also used by the Search and Flows panels).
- **The agents tree** (`Workspace::agent_rows`): agents in tab order, each followed by the agents it started; a parent outside the workspace counts as none, so the agent becomes a root rather than disappearing. A folded agent hides its descendants but still counts its children. The walk is depth first with an explicit stack and a seen set, so a cycle in the data cannot loop forever.
- **The grid keeps styles and links resolved**: each frame and patch carries its own style and hyperlink tables, indexed by its runs. Resolving runs into `Run { style, link }` on arrival means a patch's tables never have to match the ones the grid was built with.
- **A patch applies only on the frame it was made from**: its `base` must be the grid's revision, and its `surface` and `boot` the grid's. Otherwise, or when it names a pane the grid does not hold, `apply` answers `NeedRedraw` and the window asks for a complete frame (`cornercase redraw`). Panes patched before the unknown one stay patched; the redraw replaces them anyway.
- **Patch order within a pane**: the cursor is always replaced (a missing cursor hides it); `active`, `modes`, `scroll` and `colours` only when present; then `copy` moves rows from a snapshot of the lines taken before it (so overlapping ranges copy the old rows, as a scroll does), ignoring rows outside the grid; then changed rows, keyed by row number as a string, grow the grid when needed. A key that is not a number is skipped.
- **The surface falls back to complete frames** while cornercase refuses `surface --view --patches` (#461); the parsing here handles both and needs no change when patches come back.
