# Changes panel

Code: `panels/changes.rs`, `panels/changes/`, `panels/on_machine.rs` (what it shares with Files on a machine)

The workspace's git changes, through `cornercase changes`, with the actions of the TUI's panel (cornercase's `design/changes-panel.md`).

## Following

- **One stream, `changes list --follow`**, for the workspace our view shows, in one of the TUI's modes (Uncommitted, Commits, All), or `--every` for every project's uncommitted changes. Every project takes no `--mode`: it is only ever uncommitted.
- A closed panel follows nothing; opening it starts the stream again. A stream that stops says why (its standard error) instead of going quiet.
- Each restart bumps a generation, so lines from an older stream are dropped.
- Unknown values from a newer cornercase (a status, a fold class, new fields) read as `Other` or are ignored, so a summary never fails to parse.

## The selected file

- **A file's digest decides when to read its patch again**: cornercase changes it whenever the file's change does, so a new summary rereads only the files that changed, and a file that left the summary closes.
- Each read bumps a generation, so a late answer for an older version is dropped.
- While the same file keeps the same hunks, the gaps already read stay open and the scroll position is kept.
- **Gaps**: only the unchanged lines between two hunks can be read, as in the TUI; `changes gap` has none above the first hunk or below the last. `--hunk` takes the index from 0 of the hunk after the gap, as the help says since #471 upstream (checked live with cornercase 0.12.225: asking for hunk 0 is refused, the first gap is hunk 1's).
- Line runs: the highlighting's segments are cut again where the changed words start and end; emphasis comes in characters, not bytes, and segments that do not add up to the line are ignored rather than drawn wrong.
- **Shared files**: a yellow `⇄` before a file's tags and counts says another workspace of the project changes it too, with who in its tooltip, in the project scope and in Every project. The panel only reads `view`'s `shared`, so the mark costs it nothing and follows the setting (`design/shared-files.md`).
- **The file list and the diff share the panel**: until their border is dragged (`design/widgets.md`), the list fits its rows up to about a third of the room, so a few files leave the diff the rest; once dragged it keeps that height whatever the rows, always leaving the diff some lines, and a double click makes it fit again. The handle belongs to the diff's header, which is drawn after the list, so it lies over both and sits on the border even while the list fits its rows, whose height the panel does not know.

## The filter

- **A field over the file list filters by path** (`filter.rs`, plain functions tested without a window), the TUI's filter from cornercase 0.5.1 (its `design/changes-panel.md`) with the same words: each word keeps the files holding it, `!` leaves files out, `*` and `?` make it a pattern as in `.gitignore` (no `/`: any part of the path; with `/`: the whole path and what is under it; `**` crosses folders; a trailing `/` only folders), a capital makes that word case-sensitive, and a renamed file is found by either path. It filters only the list on screen, which the window already holds, so nothing goes through the command line: `changes list` has no such option and needs none.
- **It is always there while the panel holds a file**, one row of the header, under the summary. The TUI opens it with ` ⌕ ` because a row costs it a line of a terminal; here the header has the room, and a field hidden behind a button is a field nobody finds. With nothing to filter it goes, and its text stays for when files come back.
- **The summary says how many are left** (`3 of 31 files`); the lines added and removed, and a project's header under Every project, still describe every file, as in the TUI, and a header whose files all left the list hides.
- **Enter gives the keys back to the pane and keeps the filter** (`Store::give_keys_back`), Escape clears it, and on an empty field goes on to close the panel, as every search field here. A file open in the diff stays open when the filter hides its row: its review is not what the filter is about. The filter lives on the panel, so changing scope or workspace keeps it; typing goes back to the top of the list.
- Checked live on 2026-11-06 (debug build, cornercase 0.13.1, Linux x86_64 under Xvfb with lavapipe, a private server; no macOS, no Windows): `order !*.js` over six changed files, `1 of 6 files`, Enter and then typing in the pane, its text kept; Escape clearing a query and, once more, closing the panel. Every project's headers and a filter over a long list were not tried.

## A machine's workspace

Upstream's `design/changes-panel.md`, "A machine's workspace", and its `design/remote-windows/machine-panels.md`. How the choice is made and what the panels share is in `design/remote.md`.

- **With a machine's workspace picked in the sidebar the panel shows that workspace's diff as the machine computes it**: `cornercase --remote DESTINATION changes list --follow`, `changes file` and `changes gap` with its id, in the panel's mode. The tabs, the filter, the diff, the gaps, selecting and ` Copy ` work as here; each summary replaces the list at the machine's pace, and another mode opens another stream, as here.
- **Whose a file is, by type** (`Whose`): `Here(u64)` or `There(Aim)`. A followed workspace and a selected file hold one, and `Whose::arg` is the only text they give a command. A machine's rows carry numbers that mean something else here (`ThereId`, `design/machines.md`), so everything that writes, or asks this server about a workspace, takes a plain `u64` that only `Here` gives: stage, discard, viewed, the base, ` Open `, **Ask agent** and the `⇄` of shared files cannot be reached with a machine's number, as upstream's `changes_target()` being `None` turns them off. Rejected: a flag checked by each button, which a new button forgets, and a second panel entity as upstream's second `changes::Panel`, since here everything keyed by a workspace is one summary and one open file, dropped on the way out.
- **Only reading**: stage, discard, marking viewed, picking the base and opening in an editor are not offered, and the strip says `read only`. `●`, `◐`, `✓` and the base (`vs origin/main`, without `▾`) show as the machine sends them. The requests to act exist, so acting there is a follow-up that needs no new command.
- **Every project stays this computer's**, as upstream's: a base describes one repository, and folding a machine in would take a stream per workspace there. Chosen with a machine picked, the machine's stream closes, the strip goes and the summary says `uncommitted changes of every project on this computer`; its rows act on this computer's workspaces as ever.
- **A machine down keeps what is on screen**: the stream goes and the list and the open diff stay, under `vps unreachable · reconnecting…` and a footer that says `reconnecting…`. A click that needs the machine (another file, a gap) sends nothing and says so in a toast; closing the diff, the filter and copying still work. When the link is back the stream reopens over the list: its first `loading` line, with no files yet, is ignored so the list does not blink. A mode chosen while down has nothing to show, and says `Nothing read from vps`.
- **A stream that ends while the link says linked** is tried again after `cli::backoff` (1, 2, 4, 8, 15 s), counting failures until something is heard (`on_machine::Retry`), with `vps did not answer · reconnecting…` and ssh's words in its tooltip. The link can take seconds to notice what a stream already knows.
- **A server there that restarted drops what was shown**: its ids may now name another workspace, so another `boot` makes another `Aim` (`MachinePlace::followed` finds the workspace again by path and name) and the list and the open file start over. Summaries carry `boot`, so one from a server that restarted before the view's line says so is not believed: it counts as a failure and the stream is tried again. `changes file` and `changes gap` answer without `boot` and take none (#677 upstream), so the moment between a restart and the next line is still open for them; a wrong answer can only show, since nothing here writes.
- **Leaving drops the state and the stream**: a click on anything of this computer makes another `Whose`, as does another workspace or machine. A closed panel follows nothing, as here.
- **Not built, because nothing here needs it**: upstream's lazy patches (it unfolds many files; this panel opens one at a time), `↕ N more unchanged lines` (a gap is drawn whole), its cleaning of control characters (it writes to a terminal; gpui draws text), and a count on a button (the rail's icon has none).
- **Checked live** on 2026-11-06 with cornercase 0.13.1, Linux x86_64 under Xvfb with lavapipe, a fake `ssh` between two servers on one box; no real sshd, no macOS, no Windows: a change in the machine's clone listed and its diff read while this computer's clone said `No uncommitted changes`, an edit there showing without a click; Commits with `vs origin/main` at rest, All, a gap opened, a line selected with only Copy beside it, a hunk with only Copy; Every project running `changes list --every` here; a click on the local row killing the stream and bringing back this computer's list; `machines retry` with `ssh` held, keeping the list and the diff, a toast for another file, and the stream back; the stream's process killed with `ssh` still held, `vps did not answer · reconnecting…` and the list kept; `there kill-server` with an open diff, the diff dropped and the stream on the workspace's new id; a window through `--remote` on server A, whose panel says `vps is linked from a-host: its address means nothing from this computer` and runs nothing there. Not checked: a real sshd and network, two machines, a machine whose destination changes under the panel.

## Actions

- **Every action on a file names the version shown** (`--digest`, #470 upstream): the diff's digest when the file is open, the row's otherwise, so a file that changed since is left alone. A refusal is toasted in cornercase's words and the diff is read again; the stream brings the new row. The actions still go through the ordered queue (`store::queued`, or a confirmation's `on_reply`), so a quick stage then unstage keep their order.
- **Viewed** is shown at once and confirmed by the next summary. Marking takes `--digest` and no `--mode` (cornercase refuses both together); clearing takes `--mode` and no digest (`--clear` refuses one). A mark for a version that is gone is dropped silently, with no error to show, so only the next summary undoes the tick.
- **Stage** stages while anything is unstaged and unstages once everything is, as the TUI's `+`. The mark is blank when nothing is staged (a dim `+` on a hovered row), `◐` partly, `●` fully. Staging and discarding exist only in Uncommitted and Every project; `staged` is absent elsewhere.
- **Discard** always confirms, in cornercase's own words per kind of change (an untracked or added file is deleted; a rename brings the old name back). Only the version shown is discarded; the confirmation says a file that changed since is left alone.
- **Choosing a base** (`changes base BRANCH` or `--default`) is shared with every window, so the stream answers it rather than the panel.
- **Open in editor** opens a new tab of the file's workspace running `${VISUAL:-${EDITOR:-vi}} +LINE 'PATH'`, as the TUI's hunk `open`. `--view` goes before `--`: after it, it would be typed into the shell.
- **Ask agent** pastes `path:a-b ` (the new side's lines the hunk changed, or the line where lines were removed) into the workspace's agent, the shown tab's first, and focuses it, as the TUI's `ask agent`, and the keys go to it. Without an agent it copies the reference. The pull request dialog asks the same way (`Store::ask_agent`).
- **Copy** copies the hunk as a patch, as the TUI's hunk copy.
- **Choosing a base is a job**: the base button reads `switching…` until `changes base` answers, since git recomputes the diff; the diff's `updating…`, the branch list and the empty states show a spinner.
- **Staging, unstaging and discarding are jobs** keyed by the file (`actions::file_busy`): the row's stage mark turns into a spinner and the open file's buttons into `Staging NAME…` (or `Unstaging`, `Discarding`) until git answers; they keep their place in the queue (`store::queued_busy`). Marking a file viewed stays optimistic, as it was.

## Selecting lines and characters (`lines.rs`)

The TUI's 0.12.173 (lines, its #428) and 0.12.185 (characters, its #440). The hunks' three actions stay, for a whole hunk; a selection is any part of the file.

- **The viewer's rules, in one place** (`ui/selection.rs`, `design/files-panel.md`, Selecting in the viewer, for how a press, a drag, a shift-click, the floating actions, the scrolling at the edges and Escape go, and what was rejected). Only what differs is here. Wrapped lines are the default and a button cuts them instead, a setting shared with the viewer (`design/files-panel.md`, Long lines): `selection::code_cell` draws both, so a wrapped line's caret comes from gpui's `TextLayout` (`row_probe`, drawn after the text so the layout it asks is ready) and a cut line's from `ui::one_line`. On a cut line the "…" takes the tint of the changed words it hides, so a change past the edge still shows that it is there.
- **Kept by what it selected**: a `diff::Spot`, the hunk, whether a gap's line or the patch's, and the line, which sort as the rows draw. Opening a gap moves the rows and not the selection. One open file has one selection, and it goes when the hunks change (`show_patch`): a spot would name another line. A digest that changes with the same hunks keeps it.
- **A selection crosses hunks and open gaps**, over added, removed and unchanged lines in the order shown. Rows that are no lines (a hunk's header, a closed gap) stand for the line above them during a drag.
- **Only a press on nothing clears it**: a hunk's header or the blank under the rows. A hunk's buttons and a gap's row keep their actions and leave it (`selection::keep_selection`, which also stops them taking the keys from the terminal).
- **The look**: the tint stays, since it says whether a line was added or removed: stronger on a selected line, with the numbers in `accent`; an unchanged line takes `selected`. Characters take the selection's cobalt over the words' emphasis.
- **Ask agent** quotes the new side's numbers of the covered lines. Only removed lines have none, so they quote their hunk's reference (`diff::changed`), never old numbers: an agent reads `path:a-b` as the file as it is now. The bar's label names them apart (`removed lines 7-8`).
- **Open** runs the editor in a new tab at the first of those lines, as the hunk's; a deleted file has none. "Open in…" is the Files panel's, which reads the disk: this panel has only `changes file`'s answer.
- **Copy** takes the lines or characters as drawn, joined with `\n`, without signs or numbers. **`changes file` and `changes gap` give only `text`, with tabs as four spaces, so a copy cannot keep them** (#667 upstream, `design/upstream-gaps.md`). The Files panel's copy can, since it reads the file; here, reading the disk would give only the new side and reimplement the server, so when what was copied holds four spaces in a row the toast says that tabs may have become spaces and names the issue.
- **Left out**: selecting across files (the panel opens one at a time) and the hunk's Copy taking a line's own text, which needs the same field.
- **Checked live** on 2026-11-06 with cornercase 0.13.1, Linux x86_64 under Xvfb with lavapipe; no macOS, no Windows. A click, a shift-click, a drag on the numbers, characters across a wrapped removed line, with their labels; a closed gap opened under a selection, and a hunk's Copy, both leaving it; an edit that changed the hunks dropping it; Open running `nvim` at the line in a new tab; Ctrl+Shift+C and the toast. Ask agent shares the viewer's code, which was checked there. Every project and another machine were not driven.
