# Context dialog

Code: `src/model/agent_context.rs` (the serde types of `context --json`), `src/dialogs/context.rs` (the dialog and the tab menu's choices), `src/dialogs/context/` (`read.rs` what the commands answered and what the dialog says of it, `lists.rs` the words, slices and rows made from an answer), the entries in `src/tabs.rs`, `src/sidebar/menus.rs` and `src/terminal/machine_menu.rs` (a machine's pane menu, which calls `Root::view_context_there` in `src/app/machine.rs`)

- **The TUI's `view context`, as a dialog** (cornercase's `design/context-use/breakdown.md`, 0.12.243, #585 upstream; asked for on 2026-11-06, when the rows only said how full an agent's window is). When it is 40 % and `AGENTS.md` is 8 k tokens, the question is what the rest is. Claude Code's `/context` answers it, but writes into the conversation and needs the agent idle, so cornercase starts a second `claude` on the same conversation; the window only draws what `cornercase context` says.
- **Where it opens**: the pane menu of a machine's tab, which reads the machine (`design/machines.md`, #95), and `View context` in a tab's menu (the tab bar's and a sidebar tab row's) and in an agent's menu (its row, the agents section's included, and its `⋯`). Each is offered only for a pane that runs an agent as the menu opens, since a row's click can come from the frame before the agent left. A tab with several agents has one entry per agent, in pane order: `View context · claude`, `View context · codex`, `View context · claude 2`, the pane's `agent`, since `view` has no title for it and the rows already say `claude`; the TUI's title (`Claude Code`) arrives only with the answer. The pane's own menu has it too, which upstream's has not: that menu here is the agent's menu less `Show`, and a separate list would be a rule to keep in step for nothing.
- **Two commands, one after the other**: `context --pane N --cached --json`, then `context --pane N --json`. The first answers at once with the last numbers and their `age` (`Read 8m ago`), so what you last saw is on screen at once while the 3 to 10 s read runs. They are not started together: the first answer says whether a read is worth it. An agent with a `notice` and no breakdown has nothing more to say (the second command answers the same thing at once, and the dialog would flash `Reading…` for it), and a command that failed or was refused would only do so again. Nor does a read follow once the dialog has closed: gpui keeps the view for its exit animation, so a slow answer (over ssh) could still arrive in it, and would have started a second `claude` and every MCP server for nothing (CodeRabbit's review, 2026-11-06). With one command running at a time answers cannot cross, so this dialog needs no numbering, unlike the pull request's, which asks again whenever `view` changes. `Refresh` and Enter run the read alone and do nothing while one runs (`Reads::can_read`); a read costs a second `claude` and a start of every MCP server, so nothing here repeats it by itself.
- **Status 3 is an answer**: the read goes through `cli::run_partial` as a job beside the queue (`store::run_local_busy`, `Reading Claude Code's context…` in the status bar), since it only waits, and `store::run_busy` would have turned status 3 into an error and lost the numbers the answer carries. The cached one is `store::run_partial`, with no job: it answers at once, and the dialog already shows that it runs.
- **While it reads** the numbers stay and `Refresh` turns into `Reading…`, at the same width, so `Done` does not move. With no numbers yet (`age` null) a spinner under the agent's line says `Reading what fills it, 3 to 10 s…`, and `model` and `percent` already show, since even the first cached answer has them. The footer's age is `age` plus the time since that answer came, redrawn every 30 s by a timer the dialog holds, as a still window draws nothing. It stays on the last good read when one fails, since it dates the numbers.
- **A read that fails** says why in red, `Could not read the context: claude exited without answering`, with the last numbers under it: both the answer's `error` (status 3; also `Claude Code has not said yet which conversation it is in`, on an agent just started) and a command that fails (status 1, a server gone). No toast: the dialog says it where you are looking, as the pull request's does. It sits above the part that scrolls, so a read pressed at the bottom of the lists still shows it. A new read hides it until it answers.
- **An older server** is told by its refusal, as with `pull-request`, since new commands have no feature string (upstream's rule): `has no `context` command`, or clap's `unrecognized subcommand 'context'`. The dialog says `What fills an agent's context needs cornercase 0.12.243 or newer`, muted, and offers only `Done`. With a minimum above that it still happens: a server left running across an update.
- **The heading**: `Claude Code · Opus 5.5` (`title`, then `model`, the tab's name for it; a new conversation has none yet, so the breakdown's `claude-opus-5-5` stands in), then `251.9k of 1M tokens · 25%`, or `20% of its window used` without a breakdown. `auto_compact_at` is a quiet chip, `Compacts by itself at 967k`, gone when auto-compact is off. Figures are shortened as the TUI's (`2.7k`, `6k`, `1M`), not as Usage's (`2.7k`, `6.0k`, `1.0M`), so both name the same number the same way.
- **No conversation yet** (`conversation` null: no transcript, or right after `/clear`): a muted line over the bar says `No conversation yet: this is what a new conversation starts with.`, since the fixed costs are what you want to see before the first prompt.
- **The bar places a category by `kind` only, never by its name** (Claude's own string, passed through): `used` in the answer's order, in the TUI's palette by position (xterm 141, 175, 110, 180, 139, 73, 174, 146, 104: violet to indigo, none of the status colours, none of the brand's cobalt, so a slice never reads as a state), then `free`, then `buffer` at the far end, muted, as `/context` draws them. A slice is its share of `max_tokens`, at least 2 px so the small ones show. The free slice alone gives up the width that takes, and the 2 px gaps' (a shrink factor far above the others', `GIVES_WAY`), so the others keep their exact share: left to flexbox alone, every slice lost about 4 % (CodeRabbit's review). With too little free space they all shrink together. The legend lists them with tokens and share. **`deferred` is not in the bar**, which is the one difference from a plain reading of "the categories": those tokens are not in the window (used, free and buffer add up to `max_tokens` exactly: 251,853 + 715,147 + 33,000 in the fixture, with 218,839 deferred on top), so drawn they would overflow it. They fold into one muted line, `Not loaded: MCP tools 199.9k · System tools 19k`, as the TUI's. Any other kind goes nowhere, so a new one from a newer Claude breaks nothing.
- **The lists**, each only when it has something: memory files, relative to the server's home (`Session::home`, not this machine's: they differ under `--remote`), with the kind (`Project`, `AutoMem`) and tokens. The folder is muted and cut with "…" and the file's name stays whole, since names tell them apart; the TUI cuts a path at the start, which `ui::one_line` cannot. A name wider than the whole cell leaves no folder and is cut in turn, rather than run over the columns beside it (CodeRabbit's review). MCP servers (`3 of 8 tools loaded`, muted with none loaded) and their instructions are two lists and never merged, since they come in two name spaces (`claude_ai_Docs`, `claude.ai Docs`). Skills are one row (`34 skills`, `20 of 34 skills`), messages four, with the five tools that took the most after them. Not shown: `attachment_kinds`, which names Claude's internals (`hook_success`, `deferred_tools_delta`).
- **Once, quietly**: `Nothing is typed into the agent and no tokens are spent. While it reads, the agent's MCP servers start a second time.`, faint, under the part that scrolls, so it is read before pressing `Refresh` without being a warning. Not for an agent with a `notice`, since nothing starts for those. Upstream's other caveat (a read lags by the reply in progress) stays in its docs.
- **Other agents** answer `model` and `percent` with a `notice`, and that is all the dialog shows: `Codex · gpt-5.4`, `20% of its window used`, `Codex does not say what fills its context`. `Refresh` stays: both can change.
- **It closes itself** when its pane goes or runs no agent any more (a `Store` observer, as upstream's `close_gone_context`), only while it is the dialog shown, so one still animating out cannot close the next. A lost connection (no session) leaves it open.
- **Rejected**: the pull request dialog's reading again whenever `view` changes, or a minute later (each read would start every MCP server again, and `view` changes with every reply); a key of its own, which upstream's has not either.
- Nothing waits upstream here: `context --json` carries everything shown. On a machine's tab, `context` takes `--boot` from cornercase 0.13.30 on this computer; the dialog's own run check stays for older ones (`design/machines.md`).
- **Checked live on 2026-11-06** (cornercase 0.13.1, Linux x86_64 under Xvfb with lavapipe, debug build, a private server). Rather than a `CORNERCASE_BIN` wrapper answering from a fixture, the bench's `agent_commands` pointed `claude` at a fake that writes `sessions/<pid>.json` and a transcript in its own `CLAUDE_CONFIG_DIR` and, started with `-p` as cornercase starts its probe, answers from upstream's `tests/fixtures/claude/2.1.316/context-usage.jsonl`, and `codex` at one that holds a rollout open. So the real server read them, and `tests/fixtures/context/` is its real output: the read, a failed read after a good one (status 3), a first cached answer, an agent that has not said its conversation, no conversation yet, and Codex. No real agent ran. Seen in the window: the entries in a tab's menu, on the agents section's row and in the pane's menu; two agents in a tab told apart; `Read 8m ago` with the numbers under `Reading…`, then `Read just now` with the job gone from the status bar; the age moving on to `Read 1m ago` with the dialog left alone; `Refresh` by click and by Enter; a first read's spinner; status 3 (the error above the kept numbers); an agent that has not said its conversation; no conversation yet; the plain Codex dialog; closing the pane closes the dialog and no job stays; a 760×400 window, where the body scrolls with the title and buttons in view; Messages' slice at 106 px of the bar's 514 (20.6 %), and a memory file with a 110-character name, cut inside its cell with its columns in place; an older server's refusal, played by a wrapper with the words of upstream's `control.rs`. Through the bench's fake `ssh`, `cornercase --remote` was checked to keep status 3 and the answer (command line only, not a window on it). Not checked: a real `claude` or real MCP servers, a real older server, macOS and Windows (nothing in it is platform code; a Windows path has a test).
- **On a machine's tab** (#95): `Context on vps`. Both commands go through `cornercase --remote` as jobs, the cached one too, since it crosses ssh (keys `context:vps:BOOT:PANE`). Memory files show relative to the machine's home. The dialog closes when the tab leaves that run or the agent goes there, stays while the tab is down (it reads what `Root` published into `Store`, `design/machines.md`), and drops an answer that lands after either, showing why. Why it sends `--boot` only from cornercase 0.13.30 here, and keeps its own run check, is in `design/machines.md`.
