# Remote servers

Code: `cli.rs` (`Target`), `cli/remote.rs`, `dialogs/remote.rs`, `dialogs/remote/hosts.rs`, `app.rs` (`Root::switch`), `platform/paths.rs` (whose rules a path follows)

- **Every command runs as `cornercase --remote DESTINATION [--remote-command COMMAND] ARGS`** on this Mac (#476 upstream), for the app started with `--remote DESTINATION` or switched with ⇧⌘K. cornercase reaches the other machine through the user's `ssh` and `cornercase proxy` there, with the request sent in-band, so arguments and standard input never pass through a shell. `Target::Remote` is only the data (destination and command); `Remote::flags` turns it into the two flags. The window stays one more client of the documented command line (`design/connection.md`).
  - Replaced: building `ssh OPTIONS -- DESTINATION sh -c '…; exec cornercase ARGS'` here (quoting for sh, bash, zsh and fish, the `PATH` search, the ssh options). cornercase now owns all of it, with its banner and version check (a remote older than this Mac's cornercase is refused with the `update` line to run).
  - Rejected: relaunching the app for another server (the window would close and reopen, losing its place and sizes), and reading anything over ssh but the command line's answers (`design/upstream-gaps.md`).
- **What cornercase's ssh does**: the user's config, keys, agent and jump hosts apply; `BatchMode=yes` (a window has no terminal to ask for a password, so it needs a key or an agent; an unknown host key fails until `ssh DESTINATION` accepts it once in a terminal), `ConnectTimeout=10`, `ServerAliveInterval=5` and `ServerAliveCountMax=3`. A destination that starts with `-` or holds a space is still refused here, before any command runs.
  - **Lost with the switch**: the window's own shared connection (`ControlMaster`, kept 60 s), and `LogLevel=ERROR`, `RemoteCommand=none` and `ClearAllForwardings=yes`. cornercase rejected a master of its own (it would override the user's config) and documents the user's `ControlMaster auto` and `ControlPersist` instead; without one, each one-shot command pays an ssh handshake (on 2026-10-24 against a local sshd: ~45 ms alone, ~18 ms through a master). Typing (`input --follow`) and the queue's commands (`requests --follow`, `design/connection.md`) keep one ssh connection each, so what still pays a session per command is the panels' reads, the jobs and a pasted image (one session each since #557 upstream; a `--view` command used to open two, one for its `contract` check). Measured on 2026-10-31 against a Tailscale host (~55 ms round trip, cornercase 0.12.230, no master), from the command to its frame: a one-shot `focus --view` 1.2–1.4 s, `scroll` 0.65–0.8 s (0.6 s and 0.3 s through a master), a line on a link already open about 50–70 ms. A host whose config sets `RemoteCommand` now refuses commands, and its `LocalForward`s are tried by every connection.
- **On Linux nothing here changes** (read in the code on 2026-11-04): cornercase builds the ssh line, and the only ssh this window starts itself, the Browser's tunnels (`design/browser.md`), set `ControlPath=none`, so no socket path of this app has to fit a limit (108 bytes on Linux, 104 on macOS). A server of one's own for a check still needs the short `HOME` or `CORNERCASE_SOCKET` above. The text says "this Mac" on macOS and "this computer" on Linux (`desktop::machine`), as everywhere in the window.
- **"Run cornercase there with"** is `--remote-command`, which cornercase runs as sh reads it, so `~` and `$HOME` expand and `env VAR=… cornercase` works.
- **A followed stream stops on the other machine when it stops here** (#475 upstream): the proxy ends its socket when its standard input ends, so killing the local `cornercase` (a dropped `Stream`) ends the stream there too. Streams get a null standard input like local ones. Replaced: a `sh` wrapper there that killed cornercase when the standard input ssh kept open ended.
- **Switching servers starts the window's state over** (`Root::switch`): `cli::connect` sets the target and bumps its generation, the streams are killed, the server left behind gets `theme --clear`, and `window.replace_root` builds a new `Root`, keeping only the sidebar's and dock's widths and the zoom. Panels, the store and the notifier start empty, so nothing keyed by the old server's ids survives. A `Queue` belongs to the generation it was made in and its worker stops when the target changes, so keys queued for one server never reach the pane with the same id on the next. `--tab`, `--workspace` and `--project` apply to the first server only; after a switch the view starts where that server's window is.
- **Reconnecting backs off on another machine**: 1, 2, 4, 8 s, then every 15 s (`cli::backoff`, `cornercase remote`'s schedule), since ssh fails at once and retrying every 1.5 s would hammer a host that is down or refuses the key. This Mac keeps 1.5 s.
- **What only works on this Mac** (#345 upstream lets a window read its own disk): the Files panel lists, reads and searches them there through `cornercase files` (#477 upstream, `design/files-panel.md`), without the menu's apps of this Mac; the sidebar's "Open in…" is gone and "Copy path" stays; ⌘-click on a path, or on a `file://` hyperlink a program there printed, copies the path with a toast that says where it is (`Store::copy_elsewhere`), and so do the Flows sheet's buttons that open a flow's file, a run's folder or one of its files (before 2026-10-31 they opened the same path on this Mac, so nothing happened); opening a project, importing a VS Code workspace and linking a plugin ask for a path there (`dialogs::ask_path`), from its home folder or its full path there: the typed path goes as `~` or `~/…` (a relative one gets `~/` in front, and `~\` from a Windows user becomes `~/`, with every `\` after it a `/`, which a Unix server needs and a Windows one takes), which cornercase expands with the server's own home, or as the absolute path in the form that machine writes (`/…`, a drive or a share), which the server judges by its own rules (`cli::from_home`). Until 2026-11-04 the window dropped `~/` and sent a relative path, which `open` resolved from its working folder over ssh; cornercase now refuses a relative path with `--remote` (#603 upstream, its `design/remote-windows.md`, Paths) and has taken `~/…` since #477, so the window sends that (checked in cornercase's sources, `cli::reach::open_path`, and by unit tests, not live); Settings' export to a file runs without `--to` and writes the text here. Pasting an image, or dropping files, sends them there with `paste-file` (#479 upstream, `design/terminal.md`).
- **Whose rules a path follows** (`platform::paths`, decided 2026-11-04 for Windows): a path cornercase gives (a project's or workspace's folder, a link's file, a queue entry's place, a flow's file, a process's program) is the server's, and the window can drive a Linux server from Windows or a Windows server from a Mac, so such a path is judged by its own form rather than by this machine's `Path`: one that starts with a drive and a separator (`C:\`, `C:/`) or with `\\` is Windows' (`paths::Style::of_path`), where both `\` and `/` separate and the name follows the last of them; any other is Unix's, where only `/` does (a `\` is a character of a name there, as cornercase's own link rules keep it on Unix). cornercase on Windows gives plain drive paths (`C:\Users\me\proj`, never `\\?\`, its `design/windows/git-paths.md`), so the form is enough; the server does not say which system it runs, and a relative path alone cannot tell, so it takes the rules of the path it came with (a link's `relative` its `path`'s) or of the session's `home` (`Session::path_style`). Paths git prints keep `/` on every system (the Changes panel). Paths of this machine (the Files panel's disk, `~/.ssh/config`, a sound file) follow `Os::CURRENT`. Rejected: `std::path::Path` for the server's paths (on macOS `C:\Users\me\proj` is one name; on Windows `/home/me` has no drive and is not absolute), and asking the server its system (no field says it; the form of its paths does).
- **The home folder as `~`** (`paths::home_relative`, the one rule behind `ui::home_relative`, Search's project rows and the Accounts rows; five copies until 2026-11-04, two of which turned `/Users/anabel` into `~bel` under `/Users/ana`): a path inside the home folder shows as `~` and then the rest as it is, so a Windows path reads `~\proj\src`, with Windows' separator, as PowerShell takes it, Starship and oh-my-posh show it and cornercase's own notes write such paths (`~\.local\bin`). cornercase's TUI writes `~/` and then the rest with backslashes (`~/proj\src`, its `text::display_path`), a mix rejected here. On Windows the match ignores case and takes either separator, since `C:\Users\Me` and `c:\users\me` are one folder; elsewhere it is exact. The home is this machine's (`desktop::home`, `USERPROFILE` on Windows) where it always was, and the session's `home` for Search, as before; using the server's home everywhere was left for later. Checked only by unit tests on macOS.
- **It is not the Machines sheet** (`design/machines.md`): this moves the whole window to another server; that sheet lists the computers the server links to, with the window staying where it is. Neither reads the other's list, as in the TUI, and each says what the other is for. The sheet's commands go to whichever server the window is on, like every command.
- **A command on a machine has its own `Target`** (`cli::run_on`, `cli::stream_on`, `store::machines_there::machine_target`), `Target::Remote` built from the destination the list gives, beside the window's `CURRENT`, so nothing about it changes where the window is or its generation. It is a one-shot `cornercase --remote DESTINATION …`, one ssh session each, or none extra under the user's `ControlMaster`. From a window that is itself on another server the destination means nothing (it is what that server's ssh takes), so such a window shows a machine's rows, as the `view` line has them, and refuses to act or to stream its tab, saying why. A machine's tab keeps five such processes open while it shows (`design/machines.md`); each is one ssh session, or none extra under `ControlMaster`.
- **What Changes and Files read while a machine's workspace is picked** is chosen in one place without a window (`store::machine_read`, tested there): `Store::machine_read` gives the `Aim`, the destination, the workspace's path as the machine writes it, its folder with that machine's home as `~`, and how it is reached, `Reach::Up(Target)`, `Down(why)` (unreachable or connecting: the link comes back by itself) or `Refused(why)` (an older cornercase, or a window on another server, whose destinations mean nothing here: nothing promises to come back). The panels ask it on every change of `Store`, and the `Aim` and the destination say it is another place: a new `boot` or a new destination drops what they showed. A machine's tab comes from the same `Store::machine_place` (`Root::machine_place_changed`, then `Root::shown`), and `Reach` says what `Root::machine_reach` says (`Up` a connection, `Down` `Lost::Link`, `Refused` `Lost::NoWay` or `Elsewhere`, an older machine promising nothing on either), so the panels and the terminal area cannot aim at two places. Another tab of the workspace moves the tab's view and leaves the `Aim`, so the panels' streams stay. `panels/on_machine.rs` holds what both draw, the strip under the dock's title (`on vps`, the place, `read only`, the note), `Retry`, the wait after a command fails while the link says linked, and `may_ask`, the one answer to whether anything new may be asked. What each panel keeps and drops is in `design/changes-panel.md` and `design/files-panel.md`, under "A machine's workspace". The commands are the documented `--remote DESTINATION changes|files`; upstream's window opens connections of its own for these (its `design/remote-windows/machine-panels.md`), which is cornercase's own protocol and not this window's to speak.
- **The dialog** (⇧⌘K, Terminal's New Remote Connection; or a click on the status bar's connection label) lists This Mac, the current server and the `Host` names of `~/.ssh/config` (on Windows `%USERPROFILE%\.ssh\config`, the file Win32-OpenSSH reads, where an `Include` that starts with `~\` is read from the home folder as `~/` is; checked only by unit tests) and the files it `Include`s, without patterns or git forges (GitHub, GitLab, Bitbucket…), which never run cornercase; reading the user's ssh config is not reading cornercase's files. A click on a host fills both fields (its own command if it is the current one, else none) and a double click connects, so a command meant for one host is never carried to another unseen. The window saves nothing of its own to disk (`design/widgets.md`), so it keeps no list of recent servers. The machines cornercase's own window has reached are in a private file no command reads (#705 upstream), so a muted line says they are not listed and names the issue.
- **Where the window is shows**: the status bar's label starts with the host (`devbox · cornercase 0.12.190`), the window title ends with `on devbox`, and the terminal's place says `Connecting to cornercase on devbox…` or `Lost cornercase on devbox`, with ssh's reason and a button to connect elsewhere.
- **Checked live with the ssh line built here** on 2026-10-24 (macOS 26, OpenSSH 10.3p1, cornercase 0.12.190) against an sshd run as the user on 127.0.0.1:2222 with throwaway keys, reached through an `ssh` first on the PATH that adds `-F` for its config: typing, the dialog, opening a project, the Files note, losing the link (the streams there stopped), the back-off (1, 2.1, 4.2, 8.4, 15.6 s), reconnecting, and ⌘Q (the theme there was cleared). `--remote-command "env HOME=<short folder> cornercase"` gives such checks a server of their own, apart from the user's session; the folder must be short, since its socket path must fit in 104 bytes. Not checked against another machine or a Linux host.
- **Checked live through `--remote`** on 2026-10-29 (macOS 26, cornercase 0.12.225) against an sshd run as the user on 127.0.0.1 with throwaway keys and an `ssh` first on the PATH adding `-F`, with `--remote-command "env HOME=<short folder> cornercase"`: the window opening, typing through one `input --follow` (one ssh and one proxy), pasting an image (its path there), a stream's local `cornercase` killed with SIGKILL (its ssh and proxy ended), the server there killed (the window reconnected and typing came back through a new typist), and quitting (every ssh and proxy ended). Not checked: another machine, a Linux host, a host whose config sets `ControlMaster`.
- **Checked live through `requests`** on 2026-10-31 (macOS 26, cornercase 0.12.234 on both ends) against an Ubuntu host over Tailscale (~55 ms round trip), with a server of its own there (`--remote-command "env CORNERCASE_SOCKET=/tmp/<folder>/server.sock cornercase"`): seven ⌘1–3 tab switches in the window opened one ssh session, the `requests` process, and no other; through such a process (a script sending what the queue sends) a focus answered in 55–60 ms with its frame in 60–120 ms, and a scroll in about 50 ms. After that server was stopped and the window reconnected, the old process was gone and the first ⌘3 switched tabs through a new one. Not checked: a pasted image (one-shot by design) and a drag's coalescing over the network.
