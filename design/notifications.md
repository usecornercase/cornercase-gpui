# Notifications

Code: `src/notify.rs`, `src/notify/`

- **What cornercase tells the user outside the terminal**: agent notices (a toast with a "Go" button that runs `go TOKEN`, a desktop notification while the window is in the background, the sound the server chose), what programs ask of the host terminal (clipboard writes, bells), and the app's state in the status bar (an update to install, away on chat apps, keeping the machine awake).
- **One `events --notices --host --json` stream per server run**: the notifier follows the run (`boot`) the view shows, and starts again when the boot changes. A new boot also resets what this window installed or was waiting to restart, since that is now running, or gone. A generation number tells the current stream from a replaced one whose end arrives late.
- **When `events` ends** (the server stopped or refused), it is followed again after 3 s while the window is connected; the first failure with a message becomes one error toast, not one per retry.
- **Events format 1** is parsed with serde (`notify/feed.rs`); events this client does not act on (status, opened, closed…) and those of a newer server read as `Other`, so a new event kind never breaks the stream. Tests use cornercase's own fixtures in `tests/fixtures/events/` and `tests/fixtures/app/`.
- **Settings are read on each notice** (`config --json`), so a change in Settings counts from the next notice without a watcher: `desktop_notifications` off stops the desktop notification; `sound_waiting`/`sound_done` name the user's own files.
- **Sounds**: `afplay` plays the user's file when it is a readable absolute path (or `~/`, as cornercase accepts them; a relative path is refused, as cornercase refuses it), else a macOS system sound per cue (`Ping` for needs-you, `Glass` for finished). Two sounds within 1 s would overlap; the second is dropped, as cornercase's own player does.
- **macOS notifications go through `osascript`**: gpui has none for an unbundled binary. The title and body are passed as arguments to the script (`on run argv`), never spliced into it, so no text can inject AppleScript. Helpers run with no input or output and are reaped on a thread of their own.
- **On Linux** (`notify/alert.rs`, decided 2026-11-04): the command lines are plain functions of the platform, tested for both.
  - **Notifications go through `notify-send`** (libnotify), with `--app-name=cornercase`, the freedesktop `utilities-terminal` icon (every icon theme has it; the app installs no icon of its own), then `--` so a title or body starting with `-` stays text. gpui has no notification API on Linux either; talking D-Bus ourselves (`org.freedesktop.Notifications`) would add a client for what one command does. The body is not escaped for the markup some servers read: an agent's notice rarely holds `<` or `&`.
  - **The system sounds are the freedesktop sound theme's**, found in the XDG data folders (`sounds/freedesktop/stereo/`): `complete.oga` for finished, `message-new-instant.oga` (a brighter ping) for needs-you, as `Glass` and `Ping` are on macOS. cornercase's own window makes its two notes in code because Linux machines may lack the theme (its `design/sound.md`); this window keeps the system's sounds as it does on macOS, and says what to install when they are missing.
  - **The player is `paplay`, else `pw-play`, else `aplay` for a `.wav`**: `paplay` plays on PulseAudio and on PipeWire's PulseAudio server alike, while `pw-play` fails where PipeWire runs without its audio session (Ubuntu 22.04 runs it for screen sharing only), so it comes second; cornercase's player tries `pw-play` first. Both read WAV, OGG and FLAC through libsndfile; `aplay` reads WAV only, so it never gets an `.oga`. `canberra-gtk-play` was rejected: it would follow the user's chosen sound theme, but it is installed less often than either player. The player's path and the sound's reach it as they are on disk, not as text, so a `PATH` or `XDG_DATA_DIRS` folder whose name is not UTF-8 still plays (until 2026-11-04 they were made text, with such bytes replaced, and the player then failed unseen).
  - **A missing tool is one info toast per run of the window**, saying what to install (`notify-send`, a player, or the theme); then nothing more is said, so a notice never repeats it. The toast and the notice's own toast still show. A tool that runs and fails (no notification server on D-Bus, no audio device) is not reported, as on macOS. Limit: an info toast lasts 4 s, so one that comes while the window is behind may pass unseen; the next run of the window says it again.
  - **Checked live on 2026-11-04** (Debian 13 arm64 in a container, Xvfb and openbox, cornercase 0.12.280, logging stubs of `notify-send` and `paplay` first on the `PATH`): a fake `claude` (a script cornercase recognises by its name, reporting `working` then `done` through OSC 7501) finished in a tab not shown while the window was minimised, and the window ran `paplay /usr/share/sounds/freedesktop/stereo/complete.oga` and `notify-send --app-name=cornercase --icon=utilities-terminal -- "claude finished" "claude finished in demo › master"`; with a `PATH` holding only `cornercase`, the same finish gave the notice's toast and the two install toasts. `cornercase notify` does not reach `events --notices`, so it cannot test this. Not checked: a real notification server (GNOME, KDE, dunst) and real audio (the container has neither), `pw-play`, `aplay`, needs-you's sound, and the user's own sound file.
- **A toast that repeats one still shown** (same kind, text and action) replaces it with a count (`×3`) and a fresh timer, instead of stacking copies: a retry loop once filled all five places with one message. Toast text wraps inside the toast's 340 px.
- **No desktop notification while the window is active**: the toast is enough.
- **Bells**: a bell in the shown tab flashes the terminal for 160 ms; one elsewhere gives a toast saying where (`project › workspace › tab`) with a "Show" button, at most once every 30 s per pane.
- **Clipboard writes (OSC 52)** are applied and announced with the program's name, so a program cannot fill the clipboard unseen.
- **The window title** is the shown pane's own title (what its program set), else its tab's name.
- **Updates** (`notify/update.rs`): the status bar offers the release `status --app` reports; its dialog shows every changelog section after the running version and installs with `cornercase update`, or shows the command to copy when cornercase cannot replace itself (Homebrew, folders it cannot write). Without a terminal and without `--yes`, `update` never restarts the server, so the restart is a second dialog: `restart --yes` at once, or `restart --when-idle --yes`, kept running until no agent is in the middle of a turn; dropping that stream cancels the restart. A version installed by another client also offers the restart.
- **Installing turns a spinner** in the update chip and the dialog's button; **Restart now** and the away chip are jobs the status bar names until the server answers.
- **Away and keep awake** show only when they have something to say: away once a bot is paired, keep awake while held or when it cannot be held.
